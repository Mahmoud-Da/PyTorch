## 3. TorchVision Dataset and Transform

### 3.1 PyTorch Datasets

* PyTorch provides built-in datasets and base classes to define **custom datasets**.
* Use **`torchvision.datasets.ImageFolder`** for structured image directories.
* The `transform` parameter is key for preprocessing the data.

---

## 4. Applying Transforms

### 4.1 Why Use Transforms?

* Transforms prepare raw data for use with models.
* You can chain multiple transforms to manipulate the data before feeding it into the model.
* Common goals: resizing, normalization, tensor conversion, augmentation.

---

## 5. Example: Defining a Transform Pipeline

-------------------code----------------------
from torchvision import datasets, transforms
from torch.utils.data import DataLoader
-------------------code----------------------

### 5.1 Define a Transform

-------------------code----------------------
data_transform = transforms.Compose([
    transforms.Resize((64, 64)),                      # Resize to 64x64
    transforms.RandomHorizontalFlip(p=0.5),           # Augment with random flip
    transforms.ToTensor()                             # Convert to tensor (0–1 range)
])
-------------------code----------------------

### Explanation:

* **`Resize((64, 64))`**: Matches input size expected by some CV models (e.g., TinyVGG).
* **`RandomHorizontalFlip(p=0.5)`**: Adds variation to training data via augmentation.
* **`ToTensor()`**: Converts a PIL image or NumPy array to a `torch.FloatTensor` with shape \[C, H, W] and values scaled from \[0, 255] → \[0, 1].

---

## 6. Testing the Transform

### Single Image Test

-------------------code----------------------
# Assuming `img` is a PIL image:
transformed_img = data_transform(img)
print(transformed_img.shape)     # Expected: [3, 64, 64]
print(transformed_img.dtype)     # Expected: torch.float32
-------------------code----------------------

* You must pass a **PIL image**, not a NumPy array.
* This pipeline resizes, optionally flips, and converts the image.

---

## 7. Next Step

### Overview

---

### Why Use a DataLoader?

* **Purpose**: Converts a dataset into an iterable that supports batching and parallel processing.
* **Batching**: Helps train the model with smaller, manageable data chunks (batches).
* **Memory Management**:

  * Loading large datasets all at once (e.g., 100,000 images) may exhaust memory.
  * DataLoader mitigates this by loading only a batch at a time.
  * Example: A GPU with 15–16 GB memory (e.g., Tesla T4) can process small batches efficiently without running out of memory.

---

### Key Concepts

* **Batch Size**: Number of samples processed before updating the model.

  * Common value: 32 (used in the example).
  * Demonstrated starting with 1 for clarity.

* **num\_workers**: Controls parallel data loading using CPU cores.

  * More workers generally improve loading speed.
  * Use `os.cpu_count()` to determine available CPU cores.
  * Example:

    -------------------code----------------------
    import os
    os.cpu_count()
    -------------------code----------------------

* **Shuffling**:

  * For **training data**: Set `shuffle=True` to avoid learning the order.
  * For **test data**: Set `shuffle=False` for consistent evaluation.

*** 146. Creating a Helper Function to Get Class Names From a Directory ***
# Lecture 5.1: Creating a Helper Function to Get Class Names

## Objective

Create a helper function that mimics `ImageFolder`'s functionality by:

1. Scanning a target directory for class folders
2. Returning a **list of class names**
3. Returning a **dictionary mapping class names to indices**

This function will serve as a building block for our custom dataset class.

---

## Key Assumptions

* The directory structure follows the **standard image classification format**:

  -------------------code----------------------
  root/
    class1/
      img1.jpg
      img2.jpg
    class2/
      img1.jpg
      ...
  -------------------code----------------------

* Example usage directory:

  -------------------code----------------------
  data/train/pizza/
  data/train/steak/
  data/train/sushi/
  -------------------code----------------------

---

## Implementation Plan

### Step 1: Use `os.scandir()` to Traverse the Directory

We scan the target directory and extract class names from the folder names (not filenames).

### Step 2: Raise an Error If No Class Folders Are Found

We ensure the directory structure is valid. If no folders are found, raise a `FileNotFoundError`.

### Step 3: Return Both a List and a Dictionary

Return:

* `class_names`: A sorted list of class folder names.
* `class_to_idx`: A dictionary mapping each class name to a unique integer.

---

## Function Definition

-------------------code----------------------
from typing import List, Dict, Tuple
import os

def find_classes(directory: str) -> Tuple[List[str], Dict[str, int]]:
    """
    Finds class folder names in a target directory.

    Args:
        directory (str): Path to the dataset root (e.g., data/train).

    Returns:
        Tuple containing:
            - A sorted list of class names.
            - A dictionary mapping class names to integer indices.
    """

    # Step 1: Get class folder names
    classes = sorted(
        entry.name for entry in os.scandir(directory) if entry.is_dir()
    )

    # Step 2: Raise error if no class directories found
    if not classes:
        raise FileNotFoundError(
            f"Couldn't find any class folders in directory: {directory}. "
            "Please check the file structure."
        )

    # Step 3: Create dictionary mapping class names to indices
    class_to_idx = {class_name: i for i, class_name in enumerate(classes)}

    return classes, class_to_idx
-------------------code----------------------

---

## Example Usage

-------------------code----------------------
train_dir = "data/train"
class_names, class_to_idx = find_classes(train_dir)

print(class_names)      # ['pizza', 'steak', 'sushi']
print(class_to_idx)     # {'pizza': 0, 'steak': 1, 'sushi': 2}
-------------------code----------------------

* This helper function replicates part of the functionality of `torchvision.datasets.ImageFolder`.
* It will be used as a utility within our custom dataset class to handle class discovery and indexing.
* Ensures modular, reusable, and testable code for different datasets.

*** 151. Exploring State of the Art Data Augmentation With Torchvision Transforms ***
## Lecture Notes: Data Augmentation and Image Transforms in PyTorch

### 1. Custom Dataset and Data Transformation

* Previously, we created functions and classes to load a custom dataset.
* A key step in this process is **transforming the data**, particularly converting target data into tensors.

### 2. TorchVision Transforms

* We explored the `torchvision.transforms` module.
* It offers multiple image transformations:

  * `Resize`
  * `CenterCrop`
  * `FiveCrop`
  * `Grayscale`
  * `RandomTransforms` such as:

    * `RandomRotation`
    * `RandomAffine`
    * `RandomCrop`
    * `GaussianBlur`
  * `AutoAugment`, `RandomAugment`

### 3. What is Data Augmentation?

* **Data Augmentation** artificially increases the diversity of training data.
* Especially useful for image data: the same image can be manipulated by:

  * Rotating
  * Shifting (horizontal/vertical)
  * Zooming
  * Adjusting brightness, contrast, or colors
  * Cropping or shearing

**Definition**:

> Data augmentation is the process of artificially adding diversity to your training data by creating modified versions of existing data.

### 4. Purpose of Data Augmentation

* Helps improve generalization.
* Encourages the model to learn more robust and general patterns.
* Makes the model more accurate on unseen data by simulating different viewing conditions.

### 5. TrivialAugment

* A specific data augmentation technique used in recent **state-of-the-art PyTorch Vision models**.
* Introduced in a PyTorch blog post on training best-performing models.
* Utilized with the transform: `transforms.TrivialAugmentWide()`

#### Usage Example

-------------------code----------------------
from torchvision import transforms

train_transform = transforms.Compose([
    transforms.Resize((224, 224)),
    transforms.TrivialAugmentWide(num_magnitude_bins=5),
    transforms.ToTensor()
])
-------------------code----------------------

* `num_magnitude_bins`: ranges from 0 to 31, controls intensity of transformation.

  * Lower values = milder transformations
  * Higher values = more intense changes

### 6. Effect of TrivialAugment

* Applies random transformations at random intensity.
* Examples of effects:

  * Brightness/contrast change
  * Color distortion
  * Random cropping or zooming
  * Rotation
* Encourages the model to learn patterns invariant to these changes.

### 7. Visualizing the Transformations

* A function is used to apply the transform and plot sample images:

  * Shows how trivial augment manipulates each image differently.
  * Demonstrates increased variation in training examples.
  * Model is trained to recognize the object regardless of the transformations.

### 8. Practical Advice

* There is **no universal best transform** — experimentation is key.
* Look at successful recipes used by others (e.g. PyTorch blog posts).
* Try different augmentations on your own dataset.
* If one doesn’t work, switch to another and evaluate.

---

## Summary

* **Data augmentation** is essential for improving image model generalization.
* `torchvision.transforms` offers a wide variety of tools to augment data.
* `TrivialAugmentWide` is a recent technique recommended by the PyTorch team for training high-performance models.
* Try different augmentations and visualize their effects to find the best fit for your dataset.

### **What is Operator Fusion?**

**Operator Fusion** is an optimization technique used in deep learning compilers and frameworks to **combine multiple operations (or layers) into a single computational kernel**. This reduces the overhead of moving data between the CPU and GPU or between different memory units on the GPU.

Instead of executing each operation (e.g., convolution → ReLU → batch norm) separately—each involving memory read/write—**operator fusion merges them into one fused operation** that executes more efficiently.

---

### **Why It Matters**

Deep learning models often have many layers, each doing small tasks:

-------------------code----------------------plaintext
Input → Conv2d → ReLU → BatchNorm → MaxPool → ...
-------------------code----------------------

Normally, each layer:

1. Takes input from memory
2. Performs computation
3. Writes output back to memory

This **read-compute-write cycle** can become a major bottleneck, especially on GPUs where **memory bandwidth** is often the limiting factor, not raw compute.

---

### **How Operator Fusion Works**

Instead of this:

-------------------code----------------------
x = conv2d(x)
x = relu(x)
x = batchnorm(x)
-------------------code----------------------

Fusion compiles it like this:

-------------------code----------------------
x = fused_conv_relu_bn(x)
-------------------code----------------------

All three operations are executed **in one kernel**, reducing:

* Intermediate memory allocations
* Memory transfers between operations
* Latency caused by layer-by-layer execution

This leads to:

* Faster model inference/training
* Lower memory usage
* Better utilization of GPU parallelism

---

### **Where It's Used**

Modern frameworks and compilers support operator fusion:

* **PyTorch** (with TorchScript and optimized backends like TensorRT or XLA)
* **TensorFlow** (with XLA compiler)
* **ONNX Runtime**
* **TVM**
* **TensorRT**

---

### **Example: Convolution + ReLU**

Instead of:

-------------------code----------------------
y = torch.nn.Conv2d(...)(x)
y = torch.nn.ReLU()(y)
-------------------code----------------------

With operator fusion, internally the compiler produces:

-------------------code----------------------
fused_conv_relu(x)
-------------------code----------------------

This gets translated to a single, highly optimized CUDA kernel.

---

### **Benefits**

| Without Fusion        | With Fusion             |
| --------------------- | ----------------------- |
| More memory transfers | Fewer memory accesses   |
| Higher latency        | Lower latency           |
| Slower inference      | Faster inference        |
| Intermediate tensors  | No intermediate tensors |

What is Parameters in Machine Learning
In the context of machine learning and deep learning models, **a parameter** is a value that the model learns from the data during training. Parameters are what the model **adjusts** to minimize the loss function and make accurate predictions.

### Two Main Types of Parameters

1. **Weights (also called kernels in convolutional layers)**

   * Represent the strength of the connection between two neurons.
   * Multiplied with the input to transform the data as it flows through the network.

2. **Biases**

   * Added to the output after the weight is applied.
   * Help the model shift the activation function to better fit the data.

---

### Where Parameters Exist

Parameters exist in **trainable layers**, such as:

* `nn.Linear` (fully connected layers)
* `nn.Conv2d` (convolutional layers)

Layers like `ReLU`, `MaxPool2d`, `Flatten`, and `Dropout` **do not have parameters**, as they perform fixed operations and don’t need to learn anything.

---

### Example

Suppose you have a `nn.Linear(4, 3)` layer:

* Input: 4 features
* Output: 3 features

**Parameters:**

* Weights: 4 (inputs) × 3 (outputs) = **12**
* Biases: 3 (one for each output)
* **Total parameters = 12 + 3 = 15**

---

### Why Parameters Matter

* Parameters **define the capacity** of your model to learn.
* Too few parameters → underfitting (can't learn complex patterns).
* Too many parameters → overfitting (memorizes data, poor generalization).
* During training, parameters are **optimized** using algorithms like **SGD**, **Adam**, etc.

---

### In Summary

| Term      | Meaning                                        |
| --------- | ---------------------------------------------- |
| Weight    | Learnable scalar used to transform inputs      |
| Bias      | Learnable scalar added after transformation    |
| Parameter | Either a weight or a bias in a trainable layer |

### What is a Parameter in a Model?
