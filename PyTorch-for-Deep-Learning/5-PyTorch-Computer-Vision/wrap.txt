## **Introduction to Computer Vision**

### **What is a Computer Vision Problem?**

* A broad field—if a human can *see* something, it can likely be turned into a computer vision problem.
* Involves teaching machines to interpret and understand visual data (images or videos).

---

## **Examples of Computer Vision Problems**

### **1. Binary Classification**

* **Task**: Decide between two classes (e.g., *steak* vs. *pizza*).
* **Approach**: A machine learning model takes in image pixels and learns patterns that distinguish the two.
* **Learning**: The model is not explicitly told what a steak or pizza is—it learns from examples.

### **2. Multiclass Classification**

* **Task**: Identify an image from three or more categories (e.g., *sushi*, *steak*, *pizza*).
* **Application Example**: Nutrafol app

  * Upload an image of food.
  * The model classifies the image as one of 100 possible food items (e.g., chicken wings, apple, etc.).
  * Also detects whether an image is food or not.

---

## **3. Object Detection**

* **Task**: Locate specific objects within an image.
* **Example**: Identifying a car from a security camera video.

  * Useful for cases like identifying hit-and-run vehicles.
* **Goal**: Find where an object appears in an image and possibly track it.

---

## **4. Image Segmentation**

* **Task**: Divide an image into multiple meaningful parts.
* **Example**: Apple’s computational photography

  * Segmenting image parts: skin, hair, background, etc.
  * Used to enhance different regions individually.
* **On-Device**: Much of this processing happens directly on mobile devices.

---

## **5. Advanced Use Case: Tesla Autopilot**

* **Application**: Self-driving cars using computer vision.
* **Setup**:

  * Each Tesla car is equipped with 8 cameras.
  * These cameras feed data into neural networks.
  * The network transforms visual input into vectors (numerical representations).
* **Purpose**: Helps the car perceive its environment and make driving decisions.
* **Software**: Tesla uses PyTorch and custom hardware like the Dojo chip.

*** 101. Computer Vision Input and Output Shapes ***
# **Lecture Notes: Introduction to Computer Vision with PyTorch**

## **1. Overview**

* **Computer Vision (CV)**: Any problem involving visual data (e.g., images, video) can potentially be transformed into a CV problem.
* We'll focus on building **machine learning models**, especially with **PyTorch**, for computer vision tasks.

---

## **2. Inputs & Outputs in a CV Problem**

### **Example: Multi-class Classification (Food Images)**

* **Goal**: Identify images of food (e.g., sushi, steak, pizza).
* **Input**: Colored images with dimensions

  * Width = 224
  * Height = 224
  * Channels = 3 (Red, Green, Blue – RGB)

### **Why 3 Channels?**

* Digital images often use 24-bit RGB, assigning values to red, green, and blue pixels.
* Each pixel is represented by 3 values: `[R, G, B]`.

### **Numerical Representation**

* Images are converted into **tensors**: multi-dimensional arrays.
* Tensor shape: **(Batch size, Height, Width, Channels)** or **(Batch size, Channels, Height, Width)**

---

## **3. Model Outputs**

* Model predicts **class probabilities** for each category.
* Example: For a 3-class classification:

  * Output: `[0.1, 0.81, 0.09]` → highest score = class prediction.
* Output shape corresponds to the number of classes.

  * E.g., 3 classes → output shape = `[3]`
  * E.g., 100 classes → output shape = `[100]`

---

## **4. Improving Model Performance**

* Show the model more images (data) to enhance pattern recognition.
* The more diverse and larger the dataset, the better generalization on unseen images.

---

## **5. General Pattern Across CV Problems**

* Encode data numerically.
* Use a suitable ML model (e.g., for classification, detection, or segmentation).
* Ensure **input and output shapes** match the problem.

---

## **6. Model Architectures**

* **CNN (Convolutional Neural Network)**: Most common for image data.
* **Transformers**: Also perform well on vision tasks (e.g., Vision Transformers – ViTs), though CNNs remain a strong baseline.
* We'll focus on **CNNs** for now.

---

## **7. Input Tensor Shapes in Practice**

* Common input tensor shape:

  * **(Batch size, Channels, Height, Width)** → e.g., `(32, 3, 224, 224)`

    * `32`: batch size
    * `3`: color channels (RGB)
    * `224 x 224`: image dimensions
* Higher resolution (e.g., 512x512) = more data, more compute
* Batch size depends on model & hardware (e.g., 32, 64, 128)

---

## **8. Grayscale Images Example (Fashion Items)**

* Dataset: Grayscale images of clothing items (28x28 pixels)
* Follows the same process:

  * Encode data
  * Feed to ML model
  * Predict class
* Output: One of 10 clothing item classes (e.g., shirt, pants, boots)

---

## **9. Image Tensor Representations**

* Two common formats:

  1. **Channels last (NHWC)**: `(Batch, Height, Width, Channels)`
  2. **Channels first (NCHW)**: `(Batch, Channels, Height, Width)`
* PyTorch defaults to **channels first**
* Be mindful of format mismatches — incorrect order can lead to errors
* Efficient formats and library conventions vary

---

*** 102. What Is a Convolutional Neural Network (CNN) ***
# **Lecture Notes: Introduction to Convolutional Neural Networks (CNNs)**

## **Recap of Previous Lecture**

* Discussed computer vision problems, input/output shapes.
* Introduced the concept of **Convolutional Neural Networks (CNNs)** as effective models for recognizing patterns in images.

---

## **What is a Convolutional Neural Network (CNN)?**

* CNN: A type of deep learning architecture designed specifically for image data.
* Abbreviation “CNN” refers to *Convolutional Neural Network*, **not** the news network.

### **Learning Resources**

* Many good guides available online (e.g., Code Basics).
* Best resource = the one **you understand the best**.
* Images and diagrams can help, but this course focuses on **code-first learning**.

---

## **Typical CNN Architecture**

### **Components**

1. **Input Layer**

   * Takes in image data with a defined number of channels (e.g., RGB).
   * Important: input and output **shapes must align** throughout the model.

2. **Convolutional Layer**

   * Applies mathematical operations across the image using filters (kernels).
   * Performs a **sliding window operation** to extract features.
   * Formula:

     $$
     \text{Output} = \text{Bias} + \sum (\text{Weight Matrix} \times \text{Input})
     $$
   * Torch module: `torch.nn.Conv2d`

3. **Activation Function**

   * Applies non-linear transformations (e.g., ReLU).
   * Helps model non-linear relationships in data.

4. **Pooling Layer**

   * Reduces spatial size (height & width) of feature maps.
   * Helps with computation efficiency and overfitting reduction.
   * Common methods: Max Pooling, Average Pooling.

5. **Output Layer**

   * Converts the processed features into predictions.
   * Often a `Linear` (fully connected) layer with number of outputs = number of classes.

---

## **Workflow of a CNN in PyTorch**

* The model is usually defined using `nn.Sequential` or custom `nn.Module`.
* Forward pass:
  Input images → Conv layers → Activation → Pooling → Output → Prediction
* Example: Model predicts class labels from image inputs.

---

## **Important Note**

* **Infinite Variations** of CNNs exist.
* The structure shown is **just one typical configuration**.
* As you progress, you'll learn to build or use more **complex or pre-trained models** (e.g., in Transfer Learning).

---

## **Conclusion**

* CNNs are foundational to image-based deep learning.
* Best way to understand: **write and run code**.
* Don’t memorize architectures—focus on building and experimenting.

*** 106. DataLoader Overview Understanding Mini-Batches ***

## Lecture Notes: Preparing Data Loaders for FashionMNIST

### 1. **Dataset Overview**

* **Total Images**: 60,000 training images (grayscale, 28x28) from the FashionMNIST dataset.
* **Task**: Classify images into **10 clothing categories**.

### 2. **Linear vs. Non-Linear Models**

* **Question**: Can clothing images be modeled with linear decision boundaries, or is **non-linearity** required?
* **Answer**: To be tested. You can try building both a linear and non-linear model and compare performance.

---

### 3. **From Dataset to DataLoader**

* **Current Format**: `torchvision.datasets.FashionMNIST` objects (for both training and testing).
* **Goal**: Convert into `torch.utils.data.DataLoader` objects.

#### Why Use a DataLoader?

**1. Efficient Computation**

* Full dataset may not fit in memory, especially with larger datasets.
* Break data into **batches (mini-batches)** for processing.
* Example: Batch size of 32 means the model sees 32 images at a time.

**2. More Frequent Weight Updates**

* Each batch allows the model to update its weights once per batch rather than once per full epoch.
* Faster convergence and better generalization.

---

### 4. **Mini-Batch Gradient Descent**

* **Definition**: A middle-ground between full-batch and stochastic gradient descent.
* **Key Reference**: *Andrew Ng’s lecture on Mini-Batch Gradient Descent*.

---

### 5. **DataLoader Construction**

#### Code Summary

-------------------code----------------------
from torch.utils.data import DataLoader

# Define parameters
batch_size = 32

# Create DataLoaders
train_dataloader = DataLoader(
    dataset=train_data,
    batch_size=batch_size,
    shuffle=True  # Randomize data order each epoch
)

test_dataloader = DataLoader(
    dataset=test_data,
    batch_size=batch_size,
    shuffle=False  # No need to shuffle test data
)
-------------------code----------------------

#### Why Shuffle Training Data?

* Prevent the model from learning the **order** of data (e.g., all T-shirts followed by all coats).
* Encourages generalization by seeing mixed examples per batch.

---

### 6. **Visualizing the Batch Structure**

* **Total Training Samples**: 60,000
* **Total Batches**: `60000 / 32 ≈ 1875`

*** 107. Turning Our Datasets Into DataLoaders ***
## Lecture Summary: Data Loading and Mini-Batches in PyTorch

### 1. **Mini-Batches Overview**

* Instead of feeding all 60,000 images into the model at once, the dataset is split into **mini-batches**.
* **Batch size** commonly starts at 32, though it can vary by task.
* **Two main reasons** for using mini-batches:

  1. **Computational Efficiency**: Easier on memory and faster training.
  2. **Frequent Gradient Updates**: The model updates its weights more often per epoch.

---

### 2. **Setting Up the DataLoader in PyTorch**

* Import statement:

  -------------------code----------------------
  from torch.utils.data import DataLoader
  -------------------code----------------------

* **Applies to all data types**: images, text, audio, etc.

* **Hyperparameter Definition**:

  -------------------code----------------------
  BATCH_SIZE = 32
  -------------------code----------------------

---

### 3. **Creating Data Loaders**

* Use the `DataLoader` class to turn datasets into iterable batches:

  -------------------code----------------------
  train_dataloader = DataLoader(dataset=train_data, batch_size=BATCH_SIZE, shuffle=True)
  test_dataloader = DataLoader(dataset=test_data, batch_size=BATCH_SIZE, shuffle=False)
  -------------------code----------------------

* **Shuffling**:

  * **Train data** should be shuffled to avoid learning order.
  * **Test data** is usually not shuffled to keep evaluation consistent.

* **Documentation Tip**:
  Read the official [PyTorch DataLoader Documentation](https://pytorch.org/docs/stable/data.html) to understand parameters like `num_workers`, `drop_last`, `pin_memory`, etc.

---

### 4. **Inspecting DataLoader Attributes**

* Example properties of a DataLoader:

  * `batch_size`
  * `dataset`
  * `drop_last`
  * `pin_memory`
* Can check length (number of batches):

  -------------------code----------------------
  len(train_dataloader)  # ~1875 for 60,000 samples at batch size of 32
  len(test_dataloader)   # ~313 for 10,000 samples at batch size of 32
  -------------------code----------------------

---

### 5. **Understanding Shapes of Batches**

* A batch has shape:
  `(batch_size, channels, height, width)`
  Example: `(32, 1, 28, 28)`

* Corresponding labels batch: `(32,)`

* Compared to typical formats:

  * PyTorch uses **channels-first**
  * Some tools (like Keras) use **channels-last**

* Used to reshape image tensors for linear (fully connected) layers.
* Example:

  * Original shape: `[1, 28, 28]`
  * After flattening: `[1, 784]`
* Flattening turns a 2D image into a 1D feature vector.
* Flattening is necessary because linear layers expect 1D input per sample.

---

### 5. **Defining the Baseline Model**

    def __init__(self, input_shape: int, hidden_units: int, output_shape: int):
        super().__init__()
        self.layer_stack = nn.Sequential(
            nn.Flatten(),
            nn.Linear(in_features=input_shape, out_features=hidden_units),
            nn.Linear(in_features=hidden_units, out_features=output_shape)
        )

    def forward(self, x):
        return self.layer_stack(x)
-------------------code----------------------

* `nn.Linear(...)`: Fully connected layers.

*** 111. Writing Training and Testing Loops for Our Batched Data ***
# 3.3: Creating a Training Loop and Training a Model on Batches of Data

## Overview

This section focuses on creating a full training loop in PyTorch, where the model is trained and evaluated on mini-batches of data rather than the entire dataset at once. The training and evaluation are done per batch and per epoch.

---

## Key Concepts

* **Training per batch**: The optimizer updates model parameters once **per batch**, not per epoch. This is more memory-efficient and allows for faster model updates.
* **Batching with `DataLoader`**:

  * Training data is split into batches (e.g., 1875 batches of size 32 from 60,000 training images).
  * Test data is also split similarly (e.g., 313 batches of size 32).

---

## Structure of a Training Loop

### 1. Preparations

* Import progress bar: `from tqdm.auto import tqdm`
* Set seed for reproducibility
* Start timer to track training time
* Set number of epochs (e.g., `epochs = 3`) for quick experimentation

### 2. Main Training Loop

-------------------code----------------------
for epoch in tqdm(range(epochs)):
-------------------code----------------------

#### a. Print Epoch Info

-------------------code----------------------
print(f"Epoch: {epoch}")
-------------------code----------------------

#### b. Initialize Training Metrics

-------------------code----------------------
train_loss = 0
model.train()  # Set model to training mode
-------------------code----------------------

#### c. Loop Through Training Batches

-------------------code----------------------
for batch, (X, y) in enumerate(train_dataloader):
    y_pred = model(X)  # Forward pass
    loss = loss_fn(y_pred, y)  # Calculate loss
    train_loss += loss.item()  # Accumulate loss

    optimizer.zero_grad()  # Zero gradients
    loss.backward()        # Backward pass
    optimizer.step()       # Update parameters
-------------------code----------------------

* Print status every 400 batches:

  -------------------code----------------------
  if batch % 400 == 0:
      print(f"Looked at {batch * len(X)} / {len(train_dataloader.dataset)} samples")
  -------------------code----------------------

#### d. Compute Average Training Loss for Epoch

-------------------code----------------------
train_loss /= len(train_dataloader)
-------------------code----------------------

---

## Evaluation Loop (Per Epoch)

### 1. Setup

-------------------code----------------------
test_loss = 0
test_acc = 0
model.eval()  # Set model to eval mode

with torch.inference_mode():
    for X_test, y_test in test_dataloader:
        test_pred = model(X_test)  # Forward pass
        test_loss += loss_fn(test_pred, y_test).item()  # Accumulate test loss

        # Calculate accuracy
        test_acc += accuracy_fn(y_true=y_test, y_pred=test_pred.argmax(dim=1))
-------------------code----------------------

### 2. Compute Average Test Metrics

-------------------code----------------------
test_loss /= len(test_dataloader)
test_acc /= len(test_dataloader)
-------------------code----------------------

---

## Output Training Progress

-------------------code----------------------
print(f"Train Loss: {train_loss:.4f} | Test Loss: {test_loss:.4f} | Test Accuracy: {test_acc:.4f}")
-------------------code----------------------

---

## Time Tracking

* Record end time and print training duration:

-------------------code----------------------
train_time_end = timer()
print(f"Train time: {train_time_end - train_time_start} seconds")
-------------------code----------------------

* Check which device the model is using:

-------------------code----------------------
device = next(model.parameters()).device
print(f"Training on device: {device}")
-------------------code----------------------

---

## Summary of Training Steps

1. Loop through epochs
2. Loop through training batches:

   * Forward pass
   * Loss calculation
   * Zero gradients
   * Backward pass
   * Optimizer step
   * Accumulate loss
3. After training loop, compute average training loss
4. Loop through test batches:

   * Forward pass only
   * Calculate and accumulate test loss and accuracy
5. After test loop, compute average test loss and accuracy
6. Print results
7. Time the training process

---

## Notes

* **Why small number of epochs?**
  Allows quick iterations and experimentation. Training can be extended once the setup is confirmed to be working.

* **Model parameter updates per batch**
  Mini-batch gradient descent enables more frequent updates and is efficient for large datasets.

* **Accuracy Calculation**
  Use `argmax(dim=1)` on logits to get predicted labels for comparison.

### **Evaluation Function Design**

#### **Purpose**

To modularize and reuse evaluation logic across different models and data loaders.

#### **Function: `eval_model()`**

**Parameters:**

* `model`: a `torch.nn.Module`
* `data_loader`: a `torch.utils.data.DataLoader`
* `loss_fn`: a loss function (e.g., `torch.nn.CrossEntropyLoss`)
* `acc_fn`: an accuracy function

**Steps:**

1. Initialize `loss` and `acc` to 0.
2. Use `torch.inference_mode()` to disable gradient calculations.

   * `loss /= len(data_loader)`
   * `acc /= len(data_loader)`
5. Return a dictionary:

   -------------------code----------------------

       "model_name": model.__class__.__name__,
       "model_loss": loss.item(),
       "model_acc": acc
   }

## **Lecture Notes: Creating Training and Evaluation Functions in PyTorch**

### **1. Goal**

  * Follows best practices.

### **2. Functions to Create**

* `train_step`: A function to handle one training epoch.
* `test_step`: A function to handle one evaluation/testing epoch (to be created next).

---

### **3. Why Functions?**

* Training and testing loops often involve repeated logic.
* Having reusable functions:

  * Reduces redundancy.
  * Makes experiments easier to manage.
  * Encourages consistency across models and experiments.

---

### **4. Planning the `train_step` Function**

#### **Function Purpose**

* Performs one training loop using a given model, data loader, optimizer, loss function, and accuracy function.

#### **Function Signature (with type hints)**

-------------------code----------------------
def train_step(
    model: torch.nn.Module,
    dataloader: torch.utils.data.DataLoader,
    loss_fn: torch.nn.Module,
    optimizer: torch.optim.Optimizer,
    accuracy_fn,
    device: torch.device = device
):
-------------------code----------------------

#### **Parameters**

* `model`: The PyTorch model to be trained.
* `dataloader`: Training data loader.
* `loss_fn`: Loss function (e.g., CrossEntropyLoss).
* `optimizer`: Optimization algorithm (e.g., SGD).
* `accuracy_fn`: Function to calculate accuracy.
* `device`: Target computation device (CPU/GPU).

---

### **5. Step-by-Step Breakdown of `train_step`**

#### **a. Preparation**

* Set the model to training mode:

  -------------------code----------------------
  model.train()
  -------------------code----------------------
* Initialize accumulators:

  -------------------code----------------------
  train_loss = 0
  train_acc = 0
  -------------------code----------------------

#### **b. Training Loop**

For each batch:

1. **Move data to device**:

   -------------------code----------------------
   X, y = X.to(device), y.to(device)
   -------------------code----------------------
2. **Forward pass**:

   -------------------code----------------------
   y_logits = model(X)
   -------------------code----------------------
3. **Loss computation**:

   -------------------code----------------------
   loss = loss_fn(y_logits, y)
   train_loss += loss.item()
   -------------------code----------------------
4. **Prediction conversion**:

   -------------------code----------------------
   y_pred = torch.argmax(y_logits, dim=1)
   -------------------code----------------------
5. **Accuracy computation**:

   -------------------code----------------------
   train_acc += accuracy_fn(y_true=y, y_pred=y_pred)
   -------------------code----------------------
6. **Backward pass and optimization**:

   -------------------code----------------------
   optimizer.zero_grad()
   loss.backward()
   optimizer.step()
   -------------------code----------------------

#### **c. Averaging Metrics**

After the loop:

-------------------code----------------------
train_loss /= len(dataloader)
train_acc /= len(dataloader)
-------------------code----------------------

#### **d. Print Results**

-------------------code----------------------
print(f"Train Loss: {train_loss:.5f} | Train Acc: {train_acc:.2f}%")
-------------------code----------------------

* The function `train_step` will now execute a full training loop and report average loss and accuracy for the epoch.

              loss_fn: torch.nn.Module,
              accuracy_fn,
              device: torch.device = device):
    """
    Performs a testing loop step on the model using the provided data_loader.
    """
-------------------code----------------------

### **Parameters:**

* `model`: The trained model to evaluate.
* `data_loader`: DataLoader for the test dataset.

## **Steps in `test_step` Function**

1. **Initialize Metrics**

   -------------------code----------------------
   test_loss = 0
   test_acc = 0
   -------------------code----------------------

   -------------------code----------------------
   model.eval()
   -------------------code----------------------

   * Use `with torch.inference_mode():` to avoid gradient computation and speed up inference.

4. **Iterate Over Test DataLoader**

   -------------------code----------------------
   for X, y in data_loader:
       X, y = X.to(device), y.to(device)  # Send data to the appropriate device
       
       # Forward pass
       test_pred = model(X)

       # Accumulate loss

   test_loss /= len(data_loader)
   test_acc /= len(data_loader)

## **What is a CNN?**

* Key strength: Ability to **detect patterns** in images (e.g., edges, shapes, textures).

---

## **Typical CNN Architecture**

A CNN usually includes the following components:

1. **Input Layer**: Receives the image data.

> Note: The specific arrangement of layers varies by task and research updates.

## **Deep Learning Insight**

* Adding **more layers** makes the network **deeper**, hence "deep learning".
* Each layer transforms the data, extracting higher-level features.
* Layers are stacked to progressively learn more complex patterns.
* Outputs of one layer become inputs to the next.

## **Residual Connections (Brief Mention)**

* Some advanced CNNs use **residual connections**: later layers receive input from earlier layers.

## **4. CNN Model Implementation**

  * `output_shape`: number of output classes.

* **Block 1**:

  -------------------code----------------------
  self.block_1 = nn.Sequential(
      nn.Conv2d(in_channels=input_shape, out_channels=hidden_units, kernel_size=3, stride=1, padding=1),
      nn.ReLU(),
      nn.Conv2d(in_channels=hidden_units, out_channels=hidden_units, kernel_size=3, stride=1, padding=1),
      nn.ReLU(),
      nn.MaxPool2d(kernel_size=2)
  )
  -------------------code----------------------
* **Block 2**: Same structure as Block 1.

### **c. Classifier (Output Layer)**

* Composed of:

  * `nn.Flatten()` to turn the multi-dimensional tensor into a vector.
  * `nn.Linear()` for final classification (dimensions to be calculated).

  -------------------code----------------------
  self.classifier = nn.Sequential(
      nn.Flatten(),
      nn.Linear(in_features=hidden_units*X*Y, out_features=output_shape)  # X and Y to be determined
  )
  -------------------code----------------------

## **5. Forward Method**

* Define how input passes through the model:

  -------------------code----------------------
  def forward(self, x):

      print(x.shape)  # Optional debug

      print(x.shape)  # Optional debug
      x = self.classifier(x)
      return x
  -------------------code----------------------

## **7. Pooling Explanation**

## 2. **Visual Evaluation of Model Predictions**

### Goal:

* Visualize how the trained model makes predictions on random samples from the test dataset.

### Why?

* Numbers are useful (accuracy, loss), but visual feedback allows us to *see* what the model is doing.
* Helps in debugging and understanding model behavior.

---

## 3. **Function: `make_predictions()`**

### Purpose:

* Run inference on a list of test samples.
* Return prediction probabilities.

### Parameters:

* `model`: trained PyTorch model (`torch.nn.Module`).
* `data`: list of sample tensors.
* `device`: PyTorch device object (defaults to the configured device).

### Steps:

1. Set model to evaluation mode using `.eval()`.
2. Use inference context with `torch.inference_mode()`.
3. Loop through the input samples:

   * Add batch dimension using `unsqueeze(dim=0)`.
   * Move data and model to the target device.
   * Perform forward pass.
   * Apply `F.softmax()` to obtain prediction probabilities.
   * Move results to CPU for visualization and append to a list.
4. Return a stacked tensor of prediction probabilities.

---

## 4. **Preparing Random Test Samples**

### Code Outline:

1. Import Python’s `random` module.
2. Set a seed (`random.seed(42)`) for reproducibility.
3. Randomly select **9 samples** from the test dataset (`test_data`), not the DataLoader.
4. Store the images in `test_samples`, and true labels in `test_labels`.

### Why 9 Samples?

* Planning to create a 3x3 grid for visualization.

---

## 5. **Sample Inspection**

* Plot sample images using `matplotlib.pyplot.imshow()`.
* Use grayscale colormap (`cmap='gray'`).
* Add corresponding ground-truth label as the title.

---

## 6. **Running `make_predictions()`**

### Process:

* Call the `make_predictions()` function:

  -------------------code----------------------
  pred_probs = make_predictions(model=model_2, data=test_samples)
  -------------------code----------------------
* Result: A tensor of prediction probabilities for each image.

---

## 7. **Converting Probabilities to Class Labels**

* Use `torch.argmax()` across `dim=1` to convert probabilities to predicted class indices:

  -------------------code----------------------
  pred_classes = pred_probs.argmax(dim=1)
  -------------------code----------------------
