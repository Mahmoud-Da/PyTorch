## Lecture Summary: Experiment Tracking in Machine Learning

### 1. **What is Experiment Tracking?**

* **Definition**: The process of keeping a structured record of your modeling experiments to determine which ones perform best.
* **Purpose**: Helps identify what works and what doesn’t, especially as the number of models increases.

### 2. **Why Is It Important?**

* As more models are created (e.g., `model_0`, `model_1`, `model_2_v3`, etc.), tracking manually becomes chaotic.
* Helps answer:

  * Which model performs best?
  * What changes led to improvements or regressions?
  * What should be repeated or avoided in future experiments?

## **2.1: Creating Data Loaders with Manual Transforms**

### **Why Transforms Are Important**

* Pre-trained models expect data in a specific format (size, range, normalization).
* Most are trained on **ImageNet**, so replicating its preprocessing ensures optimal performance.
* Mismatched preprocessing can lead to **performance degradation**.

## **Setting Up Paths**

## **Manual Transform Pipeline**

### **Normalization Values (ImageNet)**

-------------------code----------------------
normalize = transforms.Normalize(
    mean=[0.485, 0.456, 0.406],
    std=[0.229, 0.224, 0.225]
)
-------------------code----------------------

### **Transform Composition**

-------------------code----------------------
manual_transforms = transforms.Compose([
    transforms.Resize((224, 224)),
    transforms.ToTensor(),
    normalize
])
-------------------code----------------------

* **Resize**: Ensures input images are at least 224x224 (required by most ImageNet models).
* **ToTensor**: Converts images to tensors in range \[0, 1].
* **Normalize**: Matches ImageNet data distribution.

*** 204. Turning Our Data into DataLoaders Using Automatic Transforms ***
## **Lecture Summary: Creating Data Loaders with Automatically Created Transforms**

---

### **Context**

* The goal now is to create **data loaders using automatic transforms** derived directly from model weights.

---

## **Objective**

* Apply **automatically generated transforms** to ensure custom data is processed in the **same format** as the data used to train **pre-trained models**.
* This ensures optimal performance when using transfer learning.

---

## **Automatic Transforms via TorchVision (v0.13+)**

### **TorchVision Model Weights API**

* TorchVision now supports a **multi-weight API**.
* Each pre-trained model (e.g., EfficientNet, ResNet) has associated weight classes.
* These weight classes contain a `.transforms()` method that returns the **appropriate preprocessing pipeline**.

---

### **Steps to Create Automatic Transforms**

#### 1. **Choose the Model and Import Weights**

-------------------code----------------------
from torchvision.models import EfficientNet_B0_Weights

weights = EfficientNet_B0_Weights.DEFAULT
-------------------code----------------------

* `.DEFAULT` refers to the best available pre-trained weights for that model.

#### 2. **Get the Transforms**

-------------------code----------------------
automatic_transforms = weights.transforms()
-------------------code----------------------

* This creates a transformation pipeline matching what the pre-trained model expects.

---

## **Creating Data Loaders with Automatic Transforms**

#### 3. **Pass Transforms to Data Loader Function**

Assuming the helper function `create_dataloaders()` is already defined:

-------------------code----------------------
train_dataloader, test_dataloader, class_names = create_dataloaders(
    train_dir=train_dir,
    test_dir=test_dir,
    transform=automatic_transforms,
    batch_size=32
)
-------------------code----------------------

#### 4. **Print to Verify**

-------------------code----------------------
print(f"Automatically created transforms:\n{automatic_transforms}")
-------------------code----------------------

---

## **Comparison to Manual Transforms**

| Feature         | Manual Transforms                  | Automatic Transforms                   |
| --------------- | ---------------------------------- | -------------------------------------- |
| **Flexibility** | High – user-defined                | Limited to model’s training pipeline   |
| **Risk**        | High – risk of mismatching formats | Low – guaranteed compatibility         |
| **Performance** | Depends on correctness of setup    | Optimized for target pre-trained model |

* Manual transforms allow more data augmentation/customization.
* Automatic transforms are safer for direct use with transfer learning models.

*** 205. Preparing a Pretrained Model for Our Own Problem ***
## Lecture Notes: Using Pre-trained Models in PyTorch (EfficientNet Example)

### 1. **Pre-trained Model Overview**

* A **pre-trained model** uses learned parameters from a large dataset (e.g., ImageNet).
* When using pre-trained models:

  * **Base layers are frozen** to retain learned features.
  * The **classifier head** is replaced to suit your specific problem (e.g., number of output classes).

---

### 2. **Old vs New API in `torchvision`**

#### Old Way (Before `torchvision 0.13`)

-------------------code----------------------
model = torchvision.models.efficientnet_b0(pretrained=True)
-------------------code----------------------

* This raises a **deprecation warning**:

  * `pretrained=True` is deprecated since `0.13`
  * Will be **removed in `0.15`**
  * Use the `weights` argument instead.

#### New Way (From `torchvision 0.13` onwards)

-------------------code----------------------
from torchvision.models import efficientnet_b0, EfficientNet_B0_Weights

weights = EfficientNet_B0_Weights.DEFAULT
model = efficientnet_b0(weights=weights)
-------------------code----------------------

* `weights=EfficientNet_B0_Weights.DEFAULT` uses the **best available weights**.
* Other weight options are documented on the official PyTorch site.

---

### 3. **Freezing Base Layers**

To **freeze** the model's pre-trained base:

-------------------code----------------------
for param in model.parameters():
    param.requires_grad = False
-------------------code----------------------

* Disables gradient computation for these parameters.
* Prevents updates during training, making them **unchangeable**.

---

### 4. **Modifying the Classifier Head**

#### Why?

* Pre-trained models are typically trained for 1000 classes.
* You need to replace the final layer for your specific task (e.g., 3-class classification).

#### How?

-------------------code----------------------
from torch import nn

model.classifier = nn.Sequential(
    nn.Dropout(p=0.2, inplace=True),
    nn.Linear(in_features=1280, out_features=3)  # Replace 3 with len(class_names)
)
-------------------code----------------------

* `1280` is the feature vector size of EfficientNet-B0.
* `out_features` should match the number of target classes.

---

### 5. **Device Setup and Reproducibility**

* **Send model to device** (`cpu` or `cuda`) after modifying the classifier:

-------------------code----------------------
model.to(device)
-------------------code----------------------

* **Set random seed** before creating new layers to ensure reproducibility.

---

### 6. **Model Summary**

Use `torchinfo` to inspect the model:

-------------------code----------------------
from torchinfo import summary

summary(
    model, 
    input_size=(32, 3, 224, 224),  # Batch size = 32, RGB image 224x224
    col_names=["input_size", "output_size", "num_params", "trainable"],
    col_width=20,
    row_settings=["var_names"]
)
-------------------code----------------------

* Displays:

  * Input/output shape per layer
  * Number of parameters
  * Whether each layer is trainable
* Shows that only the classifier is **trainable**, resulting in faster training.

---

### 7. **Next Step: Training & Logging**

* In the next phase, the model will be trained.
* Instead of tracking metrics in a dictionary, results will be **saved to a file**.
* Challenge: Use **TensorBoard** with PyTorch for better visualization.

---

## Summary

* Pre-trained models save time and improve performance.
* Use the **new `weights` argument** (from `torchvision 0.13+`).
* **Freeze** base layers to use the model as a feature extractor.
* **Replace the classifier head** to match the number of classes.
* Use `torchinfo` to verify model architecture.
* Prepare for training with efficient logging (e.g., TensorBoard).

### Question:

> If the pre-trained model (like EfficientNet) was not trained on pizza images, will it still work when I use it to classify **pizza**, **sushi**, and **steak**?

---

### **Short Answer:**

**Yes**, it can still work — **very well, in fact**, especially if:

* You **freeze** the base layers (pre-trained on ImageNet),
* And **train only the classifier head** on your own data (pizza, sushi, steak).

---

###  Why Does This Work?

EfficientNet and similar models are pre-trained on **ImageNet**, which contains 1,000 diverse categories — including many food items like:

* Hamburger
* Hotdog
* Spaghetti
* And sometimes even pizza-like dishes

Even if "pizza" isn't explicitly a category, the model has already **learned to extract powerful visual features**:

* Edges, textures, shapes, colors, etc.

These **generic features** are **transferable** to many tasks — including food classification — without needing to re-train the whole model.

---

PS: 
- If the pre-trained model was trained on similar foods (e.g., general food datasets like Food-101), it might still perform reasonably well through transfer learning.
- If it was trained on completely different domains (e.g., cars or animals), you’d likely need to fine-tune the model on pizza/sushi/steak images for good accuracy.

### Example Analogy:

Think of the base layers as a **feature extractor** that says:

> “This looks like a circular object with red and yellow patches.”

The classifier head then learns:

> “If I see those features together, it's probably a pizza.”

---

### Fine-Tuning Options

| Approach               | What You Do                                | When to Use                                                 |
| ---------------------- | ------------------------------------------ | ----------------------------------------------------------- |
| **Feature Extraction** | Freeze base layers, train only the head    | When you have a **small dataset**                           |
| **Fine-Tuning**        | Unfreeze some/all base layers and re-train | When you have a **larger dataset** and want better accuracy |

---

### Takeaway

Even if the original model didn't see pizza specifically, it saw enough **similar patterns** to help distinguish it from other foods when trained with your dataset.

So yes — **using a pre-trained model is absolutely effective** for pizza/sushi/steak classification.

*** 230. Replicating a Vision Transformer - High Level Overview ***
## Lecture Notes: Conceptual Overview of the Vision Transformer (ViT)

### Objective

Start transitioning from dataset preparation to replicating the **Vision Transformer** architecture using PyTorch, based on the official research paper.

---

### Key Resources from the Paper

To replicate ViT accurately, focus on these **four key components** of the paper:

1. **Figure 1** — Visual overview of the architecture.
2. **Section 3.1 (Method)** — Textual explanation of how ViT works.
3. **Four equations** — Define the mechanics of the transformer, especially **self-attention**.
4. **Table 1** — Lists model configurations (e.g., ViT Base, Large, Huge).

> You’re encouraged to read Section 3.1 multiple times for a deeper understanding.

---

### Additional Reference: Table 3

* **Batch size**: 4096 (used in original paper, but too large for most local setups)
* **Image size**: 224 × 224
* **Patch size**: 16 × 16

Note: We are using **ViT-Base** but building it in a flexible way to support scaling up later.

---

### Breaking Down Complex Architectures: A Systematic Approach

To understand and replicate deep learning architectures (like ViT), break them into five components:

#### 1. **Inputs**

* Data going into the model.
* For ViT: batches of image tensors of shape `[batch_size, 3, 224, 224]`.

#### 2. **Outputs**

* Data coming out of the model.
* For ViT in this project: classification labels (e.g., `'pizza'`, `'steak'`, `'sushi'`).

#### 3. **Layers**

* Fundamental building units of the model.
* Each layer takes an input and transforms it using operations (e.g., **self-attention**, **linear layers**, **normalization**).

#### 4. **Blocks**

* A collection of multiple layers.
* For example, a **Transformer Encoder Block** includes:

  * Layer normalization
  * Multi-head self-attention
  * Feed-forward network

#### 5. **Model**

* A full model is a **stack of blocks**.
* Inputs are progressively transformed through each block until the final output is generated.

> This modular breakdown (inputs → layers → blocks → model → outputs) is crucial when implementing complex architectures like ViT.

---

### Self-Attention Refresher

* Core mechanism of transformers.
* Operates on **query (Q)**, **key (K)**, and **value (V)** vectors.
* Formula:

  $$
  \text{Attention}(Q, K, V) = \text{softmax} \left( \frac{QK^T}{\sqrt{d_k}} \right) V
  $$

> In **self-attention**, Q, K, and V come from the same source (hence "self").

---

### Implementation Plan

We’ll follow this implementation roadmap:

1. Start with **inputs** (image patches).
2. Build **layers** (e.g., patch embedding, attention).
3. Group layers into **blocks** (Transformer Encoder).
4. Stack blocks to form the **model**.
5. Train the model to predict **outputs** (food classes).

---

### Summary Recap (in terms of architecture)

| Component | Description                                      |
| --------- | ------------------------------------------------ |
| Inputs    | Image tensors                                    |
| Outputs   | Class labels                                     |
| Layers    | Functional units (attention, MLP, normalization) |
| Blocks    | Stacked layers forming encoder modules           |
| Model     | Collection of blocks                             |

## Deep Dive: Figure 1 – Architecture Overview

### What Figure 1 Shows

* An **image** is input.
* **Split into fixed-size patches.**
* **Each patch is linearly embedded** and has **position embeddings** added.
* This is passed into a **transformer encoder** with:

  * Normalization layers
  * Multi-head attention
  * Residual connections
  * MLP (multi-layer perceptron)

### Important Concepts:

* **Embedding** = Learnable representation
  → Initialized with random values, optimized over time.
* **Position Embedding** = Encodes the position of patches.
* **MLP** = Two-layer fully connected network (in this case).
* **Residual (Skip) Connection** = Adds original input to later outputs to preserve information.
* **Transformer Encoder** = A stack of blocks (Norm + Attention + Norm + MLP).
* **Block** = A set of layers grouped together.

## Understanding Equation 1

### Step-by-Step Summary:

1. **Input**: Image $X \in \mathbb{R}^{H \times W \times C}$

   * $H$: Height
   * $W$: Width
   * $C$: Color channels

2. **Patch Conversion**:

   * Image is split into square patches of size $P \times P$
   * The total number of patches:

     $$
     N = \frac{HW}{P^2}
     $$
   * Each patch is flattened and represented as a vector

3. **Patch Embeddings**:

   * Each flattened patch is linearly projected (embedded) to a vector of dimension $D$ using a **trainable projection**
   * This is referred to as the **Patch Embedding**

4. **Input Sequence**:

   * After projection, patches are turned into a sequence of vectors

     $$
     x_p \in \mathbb{R}^{N \times (P^2 \cdot C)}
     \rightarrow \text{Embedding} \rightarrow \mathbb{R}^{N \times D}
     $$
   * A **learnable class token** is prepended to the sequence
   * **Position embeddings** are added to retain patch order

## Additional Notes

### Terminology Clarification

| Term               | Meaning                                                               |
| ------------------ | --------------------------------------------------------------------- |
| $\mathbb{R}$       | Set of real numbers (image pixel values are real numbers)             |
| Patch Embedding    | Flattened image patches mapped to a latent space using a linear layer |
| Learnable          | Trainable through backpropagation                                     |
| Linear Projection  | A linear layer (no activation) that transforms input dimensions       |
| Position Embedding | Encodes positional information of patches in the sequence             |
| Class Token        | A learnable vector added to the beginning of the patch sequence       |
