# Demonstration: Creating Synthetic Data with Known Parameters

To demonstrate this, the lecture uses **linear regression**.

### What is Linear Regression?
- A simple mathematical model to describe a straight-line relationship:
-------------------code----------------------
y = a + b*x
-------------------code----------------------
  - `a` is the intercept (value of `y` when `x = 0`)
  - `b` is the slope or gradient

Slope:
- The steepness of a line.
- Tells you how much y changes when x increases by 1.

Example: If slope = 2, then for every step right (x+1), y goes up by 2.

Intercept (y-intercept):
- Where the line crosses the y-axis (when x=0).
Example: If intercept = 3, the line passes through (0, 3).

Quick Comparison:
Slope (b): "How steep?"
Intercept (a): "Where does it start on the y-axis?"



This can also be written as:
-------------------code----------------------
y = weight * x + bias
-------------------code----------------------

In machine learning terminology:
- **Weight** = slope (`b`)
- **Bias** = intercept (`a`)
- These are also referred to as **parameters**, which are the values the model learns.

---

### **Practical Example: Creating a Train-Test Split**

- We'll use an **80/20 split**, which is a common practice.

## **1. Gradient Descent**

### **What it is:**
Gradient Descent is an **optimization algorithm** used to minimize a **loss function** by adjusting the model's parameters (like weights and biases).

### **Why it’s important:**
The goal of training a machine learning model is to make accurate predictions. To do that, the model needs to **minimize the error** (difference between predicted and actual values). Gradient descent helps achieve that.

### **How it works (intuition):**
Think of it like trying to find the **lowest point in a valley (the minimum of a function)**:

1. Start at a random point (random weights).
2. Look around to see in which direction the slope goes down (compute the gradient).
3. Take a small step downhill (update the weights).
4. Repeat until you’re at the bottom (minimum loss).

### **Mathematically:**
If `w` is a weight and `L(w)` is the loss function:

-------------------code----------------------
w_new = w_old - learning_rate * gradient_of_L_with_respect_to_w
-------------------code----------------------

The **learning rate** controls how big your steps are.

---

## **2. Backpropagation**

### **What it is:**
Backpropagation is the **algorithm** used to **compute the gradients** needed for gradient descent.

### **Why it’s important:**
To know how to adjust each weight, the model needs to understand how changing a weight affects the loss. Backpropagation does exactly that by using **the chain rule of calculus**.

### **How it works (in steps):**
1. Perform a **forward pass**: Compute the output of the network with current weights.
2. Compute the **loss**: Measure how far off the prediction is from the actual value.
3. **Backpropagate**: Go backwards through the network to compute the gradient (how much each weight contributed to the loss).
4. Use **gradient descent** to update weights using those gradients.

---

## **Quick Analogy:**
Imagine you're blindfolded on a hilly terrain trying to reach the lowest point:

- **Gradient Descent** is how you figure out which direction to move to go downhill.
- **Backpropagation** is how your brain processes feedback from your steps (how steep the hill is in each direction) so you can adjust your next move.

# Loss Functions, Optimizers & Training Loops in PyTorch**


## **1. What is a Gradient?**

A **gradient** is just a fancy word for **slope** or **direction of change**.

Imagine you're on a hill and you're blindfolded.  
You want to get to the bottom of the hill (lowest point = **minimum**).

The **gradient** tells you:
- Which **direction** to go to get down the hill fastest.
- How **steep** the hill is in that direction.

### In Machine Learning:
- The "hill" is your **loss function** (how wrong the model is).
- The **gradient** tells the model how to **change its parameters** (like weights and bias) to make the loss smaller.

So, during training, the model uses the **gradient** to **learn** how to improve its predictions step by step.

## **2. Inside the Optimizer**
- Optimizers require:
  - `params`: model parameters (e.g., weights and biases).
  - `lr` (learning rate): controls how much to change the parameters.
- **Learning Rate (LR)**:
  - A **hyperparameter** (set by the engineer, not learned).
  - Small LR → small updates.
  - Large LR → large updates.

## **3. Choosing a Loss Function and Optimizer**
- **Problem-specific**.
- For regression:
  - Use **L1 loss**.
  - Use **SGD (Stochastic Gradient Descent)** as the optimizer.
- For classification:
  - Use a classification loss like binary cross-entropy.

---

## **4. Training Loop Overview**
### **Goal**: Reduce the loss through multiple passes over the data.

### **Steps of the Training Loop**
0. **Loop through the data**:
   - Called an **epoch**: one full pass through the dataset.
1. **Set model to training mode**:
   - `model.train()`
   - Enables gradient tracking.
2. **Forward Pass**:
   - Pass data through the model to make predictions.
   - Called **forward propagation**.
3. **Calculate Loss**:
   - Compare predictions with ground truth.
4. **Zero Gradients**:
   - `optimizer.zero_grad()` to reset gradients before each update.
5. **Backward Pass**:
   - `loss.backward()` calculates gradients via **backpropagation**.
   - Computes gradients of the loss with respect to model parameters.
6. **Optimizer Step**:
   - `optimizer.step()` updates the parameters using **gradient descent**.

---

## **5. Gradient Intuition**
- **Gradient** = slope (change in y / change in x).
- Imagine loss as the height of a hill:
  - The model starts at the top.
  - It follows the slope downhill (i.e., reduces the gradient).
  - Goal: reach the bottom where gradient = 0 → loss minimized.

---

## **6. Epochs and Hyperparameters**
- **Epoch**: one full cycle of training data through the model.
- `epochs` is a hyperparameter (you define how many).
- The more data or complexity, the more epochs may be needed.

---

## **7. Model Modes in PyTorch**
- `model.train()`:
  - Enables gradient tracking (`requires_grad=True`).
- `model.eval()` or using `torch.no_grad()`:
  - Turns off gradient tracking (used during inference/testing).

## **What is Gradient Tracking in Machine Learning?**

### **Definition**:
**Gradient tracking** means **keeping track of operations done on tensors so we can calculate gradients automatically during backpropagation**.

This is especially important for training neural networks, where we want to know:
> "How should we adjust each parameter to reduce the loss?"

---

### **Why do we need it?**
In training, we update model parameters using **gradients**, which are computed by taking derivatives of the loss function **with respect to** the parameters.

- To compute these gradients **automatically**, libraries like **PyTorch** record all the operations (like addition, multiplication, etc.) done on tensors.
- This "recording" is called **gradient tracking**.
- When we call `.backward()`, PyTorch walks back through this recorded graph and computes the gradients.

---

### **In Practice (PyTorch example)**:
-------------------code----------------------
import torch

x = torch.tensor(2.0, requires_grad=True)
y = x**2 + 3*x

y.backward()
print(x.grad)  # Output: 7.0
-------------------code----------------------

- `requires_grad=True` enables **gradient tracking** for `x`.
- PyTorch tracks the computation `x**2 + 3*x`.
- Calling `backward()` computes the derivative of `y` with respect to `x` (i.e., dy/dx = 2x + 3).

---

### **When to Enable or Disable Gradient Tracking**
- **Enable (default for training)**:
  - When you're training a model and need to update weights.
- **Disable**:
  - When you're evaluating or doing inference (no learning).
  - Saves memory and speeds things up.

-------------------code----------------------
with torch.no_grad():
    output = model(data)
-------------------code----------------------

---

### **Summary**
- Gradient tracking = automatic bookkeeping for computing gradients.
- Used during training to enable learning via backpropagation.
- Can be turned off during inference to save resources.

-------------------code----------------------
optimizer.step()

# PyTorch Training Loop Recap & Introduction to Backpropagation and Optimization

## Overview
This lecture recaps the steps of a training loop in PyTorch and explains key concepts such as forward and backward passes, gradient descent, and optimizer behavior. The goal is to understand the flow of training a model before moving into testing.

---

## 1. **Training Loop Overview**
- A *training loop* runs for a defined number of **epochs**.
- **Epoch**: One complete forward pass through the entire dataset.
- **Training loop purpose**: Enables the model to learn patterns from training data.

---

## 2. **Steps in Each Epoch**

### A. Set Model to Training Mode
-------------------code----------------------
model.train()
-------------------code----------------------
- Prepares the model to track gradients.
- Enables training-specific behaviors like dropout.

### B. Forward Pass
-------------------code----------------------
y_pred = model(X_train)
-------------------code----------------------
- Passes training data through the model.
- Calls the model’s custom `forward()` method.

### C. Calculate Loss
-------------------code----------------------
loss = loss_fn(y_pred, y_train)
-------------------code----------------------
- Compares model predictions to actual labels.
- Depends on the chosen **loss function** (e.g., L1, L2).

### D. Zero Optimizer Gradients
-------------------code----------------------
optimizer.zero_grad()
-------------------code----------------------
- Prevents accumulation of gradients from previous steps.
- Necessary before backpropagation.

### E. Backward Pass (Backpropagation)
-------------------code----------------------
loss.backward()
-------------------code----------------------
- Calculates gradients of all parameters with `requires_grad=True`.
- PyTorch uses `autograd` to perform automatic differentiation.

### F. Optimizer Step
-------------------code----------------------
optimizer.step()
-------------------code----------------------
- Updates parameters using the calculated gradients.
- Attempts to minimize the loss function.

---

## 3. **Concepts Behind the Scenes**

### A. Forward & Backward Propagation
- **Forward Propagation**: Input → Output through the network.
- **Backward Propagation**: Calculates gradients by moving from output → input.

### B. Gradients and Loss Curves
- Gradient = Slope of the loss function curve.
- Used to determine direction of parameter updates.
- Goal: Find the point where gradient = 0 (minimum loss).

### C. Gradient Descent
- Optimization algorithm that updates parameters in the opposite direction of the gradient.
- Visualized as stepping downhill on a curve toward the lowest point (minimum loss).

---

## 4. **Optimizer and Learning Rate**

### Optimizer Configuration
-------------------code----------------------
optimizer = torch.optim.SGD(params=model.parameters(), lr=0.01)
-------------------code----------------------
- `params`: Parameters to optimize (usually `model.parameters()`).
- `lr` (learning rate): Size of each optimization step.

### Learning Rate Insights
- **Too large**: May overshoot minimum.
- **Too small**: Slow convergence.
- **Learning Rate Scheduling**: Reduce step size over time for better convergence.

---

## 5. **Function Abstraction**
- Training steps can be wrapped in a function for reuse.
- Recommended ordering:
  1. Forward pass
  2. Calculate loss
  3. Zero gradients
  4. Backward pass
  5. Optimizer step

what is Python's pickle format ?
Python's **pickle** format is a way to **save and load Python objects** (like variables, lists, dictionaries, models, etc.) to and from a file.

### Here's a simple explanation:

- **Pickling** = turning a Python object into a file (a byte stream).
- **Unpickling** = reading that file and turning it back into the original Python object.

### Why use pickle?
- To **save your work** (like saving a trained ML model or a large dataset).
- To **share data** between Python programs without re-computing or re-loading from scratch.

---

### Example:

-------------------code----------------------  
import pickle

# Some data
my_dict = {"name": "Alice", "age": 30}

# Save (pickle) it
with open("data.pkl", "wb") as f:
    pickle.dump(my_dict, f)

# Load (unpickle) it
with open("data.pkl", "rb") as f:
    loaded_dict = pickle.load(f)

print(loaded_dict)  # Output: {'name': 'Alice', 'age': 30}
-------------------code----------------------  

---

### Things to note:
- Pickle is **Python-specific**. You can't load a pickle file in other programming languages easily.
- Be **careful when unpickling** files from untrusted sources—it can execute arbitrary code (i.e., it can be unsafe).
