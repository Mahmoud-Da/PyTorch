*** 171. What Is Going Modular and What We Are Going to Cover ***
## **Lecture Summary: What is Going Modular?**

### **1. Purpose of the Section**

* The goal of this section is to **"go modular"**: turning reusable notebook code into **modular Python scripts**.
* Focus is on **reusability**, **organization**, and **scalability** of PyTorch projects.

---

### **2. Why Go Modular?**

* Notebooks are great for experimentation and visualization.
* However, reusable code (e.g., training loops, data loaders) should be extracted into Python scripts.
* Modular code allows:

  * Easy reuse across projects.
  * Cleaner project structure.
  * Easier collaboration and scalability.

---

### **3. Project Recap: FoodVision Mini**

* Dataset: Images of pizza, steak, and sushi.
* Tasks previously done:

  * Loaded and transformed data.
  * Built and trained a PyTorch model.
  * Made predictions (with moderate accuracy).

---

### **4. Modular Directory Structure**

By the end of this section, the project structure will look like:

-------------------code----------------------
going_modular/
│
├── going_modular/
│   ├── data_setup.py        # Handles data preparation
│   ├── engine.py            # Contains training/testing functions
│   ├── model_builder.py     # Builds PyTorch models
│   ├── train.py             # Trains a model using modular components
│   ├── utils.py             # Miscellaneous helper functions
│
├── models/                  # Stores saved models
├── data/                    # Image data in standard format
-------------------code----------------------

---

### **5. Training from the Command Line**

You will be able to train a model using a single command:

-------------------code----------------------
python train.py --model tiny_vgg --batch_size 32 --learning_rate 0.001 --num_epochs 10
-------------------code----------------------

* These are called **argument flags**.
* More hyperparameters can be added, making it customizable.
* Mimics real-world usage (e.g., Meta's [Detectron2](https://github.com/facebookresearch/detectron2), PyTorch Vision scripts).

---

### **6. Real-World Examples**

* `train.py` scripts are standard in production-level ML codebases (e.g., Meta, PyTorch).
* Common patterns:

  * Scripts accept hyperparameters via command line.
  * Modular structure improves maintainability and reproducibility.

---

### **7. Workflow Overview**

**Notebook → Python Scripts Workflow**:

1. Start in Jupyter or Google Colab for prototyping.
2. Identify reusable code.
3. Move useful cells into `.py` scripts.
4. Execute via command line with custom arguments.

---

Two parts of this section:

### **9. Summary of Python Scripts**

Each component of the model pipeline is separated into its own script:

*** 175. Creating a Python Script to Create Our PyTorch DataLoaders ***
## **Lecture Summary: Writing a Python Script for Data Loaders (PyTorch)**

### **Overview**

In this session, the instructor guides us through writing and finalizing a Python script to handle data loading in a PyTorch project. The script includes:

* Creating datasets and dataloaders for training and testing
* Returning class names

---

### **1. Recap from Previous Lecture**

### **2. Completing the Data Loading Logic**

#### **Dataset Creation**

Used `ImageFolder` from `torchvision.datasets`:

 -------------------code----------------------
train_data = datasets.ImageFolder(train_dir, transform=transform)
test_data = datasets.ImageFolder(test_dir, transform=transform)
 -------------------code----------------------

#### **Class Names Extraction**

 -------------------code----------------------

 -------------------code----------------------

---

### **3. Creating DataLoaders**

Imported `DataLoader`:

 -------------------code----------------------
from torch.utils.data import DataLoader
 -------------------code----------------------

#### **Train DataLoader**

 -------------------code----------------------
train_dataloader = DataLoader(
    dataset=train_data,
    batch_size=batch_size,
    shuffle=True,
    num_workers=num_workers,
    pin_memory=True
)
 -------------------code----------------------

#### **Test DataLoader**

 -------------------code----------------------
test_dataloader = DataLoader(
    dataset=test_data,
    batch_size=batch_size,
    shuffle=False,
    num_workers=num_workers,
    pin_memory=True
)
 -------------------code----------------------

---

### **4. Explanation of `pin_memory=True`**

* Used to optimize data transfer between CPU and CUDA-enabled GPU
* Reduces bottlenecks during training by keeping memory on the GPU
* Recommended when using `DataLoader` with CUDA devices

#### **Further Reading:**

* PyTorch documentation for [`pin_memory`](https://pytorch.org/docs/stable/data.html#torch.utils.data.DataLoader)
* Horus.io’s article on deep learning speed optimization: "Make Deep Learning Go BRR"

*** 178. Turning Our Utility Function to Save a Model into a Python Script ***
### **Lecture Summary: Creating `utils.py` for Utility Functions**

#### **Objective**

To modularize utility logic—specifically the function to **save a model**—into a separate Python script named `utils.py`. This continues the modular approach initiated with `engine.py`.

---

### **Review and Rationale**

* In the last lecture, `engine.py` was created to encapsulate the training and evaluation steps.
* A natural next step is to refactor the **model-saving logic** into its own utility module.
* While we could have started with scripts from the beginning, writing the code manually in notebooks provided a valuable learning experience.

---

### **Why Use a `utils.py` File?**

* **Purpose**: Store various utility functions that support training and evaluation.
* **Reference**: The structure mirrors how the official [PyTorch `torchvision` repo](https://github.com/pytorch/vision) organizes training scripts—e.g., `train.py`, `transforms.py`, and `utils.py`.
* Example functions in `utils.py` from PyTorch:

  * `save_on_master`
  * `store_model_weights`
* These files often include docstrings following a consistent style (e.g., Google-style), similar to what we're now practicing.

---

### **Creating `utils.py`**

#### **Step-by-Step**

1. **Subheading in the Notebook:**

   -------------------code----------------------
   ## 4.2 Create a file called utils.py with utility functions
   -------------------code----------------------

2. **Writing the Script with Jupyter Magic:**

   -------------------code----------------------
   %%writefile going_modular/utils.py
   """
   Contains various utility functions for PyTorch model training.
   """
   import torch

   def save_model(model: torch.nn.Module,
                  target_dir: str,
                  model_name: str):
       """
       Saves a PyTorch model to a target directory.

       Args:
           model (torch.nn.Module): A PyTorch model to save.
           target_dir (str): Directory to save the model file.
           model_name (str): Filename for the saved model.
       """
       model_path = target_dir + "/" + model_name
       torch.save(obj=model.state_dict(), f=model_path)
   -------------------code----------------------

3. **Key Notes:**

   * **Always import dependencies** within the script (e.g., `import torch`). Forgetting to do this will lead to runtime errors.
   * `save_model()` is currently the only function, but more can be added as the project grows.

---
