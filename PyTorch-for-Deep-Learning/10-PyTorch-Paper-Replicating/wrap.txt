  *“An Image is Worth 16x16 Words: Transformers for Image Recognition at Scale.”*
* The goal is not just to understand the paper theoretically, but also to turn it into **working PyTorch code**.

---

## What is a Transformer in Machine Learning?

* A **transformer** is a deep learning model that relies on **self-attention** as its primary mechanism.
* Unlike CNNs (which use convolutional layers), transformers process input by **differentially weighting** its components.
* Originally developed for **Natural Language Processing (NLP)** but now also widely used in **Computer Vision** (e.g., ViT).
* The ViT model applies transformer architecture to image recognition tasks.

---

## Anatomy of a Machine Learning Research Paper

Most machine learning papers follow a standard structure:

### 1. **Abstract**

* A brief overview of the paper's purpose, methods, and key findings.

### 2. **Introduction**

* Outlines the main problem and the motivation.
* Describes what previous work has done and what this paper contributes.

### 3. **Related Work**

* Summarizes prior research that the current study builds upon or contrasts with.

### 4. **Method**

* Detailed explanation of the proposed approach or model.
* Often includes mathematical equations describing the model (e.g., in PyTorch terms).
* Similar to a **recipe**: describes how to reproduce the results.

### 5. **Experiments**

* Describes experimental setup: datasets used, hyperparameters, training procedures.
* Includes figures, visuals, and model architecture diagrams for better understanding.

### 6. **Results**

* Presents the outcomes of experiments.
* Includes comparisons with previous work or baselines.

### 7. **Conclusion**

* Summarizes key findings.
* Suggests possible future directions for research.

### 8. **References**

* Lists all prior works cited throughout the paper.
* For example: the ViT paper references *“Attention Is All You Need” (Vaswani et al., 2017)*, which introduced the original Transformer architecture.

### 9. **Appendix** (Optional)

* Contains supplementary material: extended experiments, proofs, additional visualizations.

> Note: Section names may vary slightly from paper to paper. This structure is flexible, not rigid.

---

## Importance of Reading Research Papers

* Research papers are **collaborative efforts by top experts**, and it’s normal not to understand them on first read.
* With **repeated practice**, understanding improves.
* Reading papers is a **key part of participating in ML research**.
* The paper discussed (ViT) is an example of applying **transformer models to vision**, a relatively recent but impactful area in ML.

## Lecture Notes: Conceptual Overview of the Vision Transformer (ViT)

### Objective

---

### Key Resources from the Paper

To replicate ViT accurately, focus on these **four key components** of the paper:

1. **Figure 1** — Visual overview of the architecture.
2. **Section 3.1 (Method)** — Textual explanation of how ViT works.

> You’re encouraged to read Section 3.1 multiple times for a deeper understanding.

---

### Additional Reference: Table 3

* **Batch size**: 4096 (used in original paper, but too large for most local setups)
* **Image size**: 224 × 224
* **Patch size**: 16 × 16

Note: We are using **ViT-Base** but building it in a flexible way to support scaling up later.

---

### Breaking Down Complex Architectures: A Systematic Approach

To understand and replicate deep learning architectures (like ViT), break them into five components:

#### 1. **Inputs**

* Data going into the model.
* For ViT: batches of image tensors of shape `[batch_size, 3, 224, 224]`.

#### 2. **Outputs**

* Data coming out of the model.
* For ViT in this project: classification labels (e.g., `'pizza'`, `'steak'`, `'sushi'`).

#### 3. **Layers**

* Fundamental building units of the model.
* Each layer takes an input and transforms it using operations (e.g., **self-attention**, **linear layers**, **normalization**).

#### 4. **Blocks**

* A collection of multiple layers.
* For example, a **Transformer Encoder Block** includes:

  * Layer normalization
  * Multi-head self-attention
  * Feed-forward network

#### 5. **Model**

* A full model is a **stack of blocks**.
* Inputs are progressively transformed through each block until the final output is generated.

> This modular breakdown (inputs → layers → blocks → model → outputs) is crucial when implementing complex architectures like ViT.

---

### Self-Attention Refresher

* Core mechanism of transformers.
* Operates on **query (Q)**, **key (K)**, and **value (V)** vectors.
* Formula:

  $$
  \text{Attention}(Q, K, V) = \text{softmax} \left( \frac{QK^T}{\sqrt{d_k}} \right) V
  $$

> In **self-attention**, Q, K, and V come from the same source (hence "self").

---

### Implementation Plan

We’ll follow this implementation roadmap:

1. Start with **inputs** (image patches).
2. Build **layers** (e.g., patch embedding, attention).
3. Group layers into **blocks** (Transformer Encoder).
4. Stack blocks to form the **model**.
5. Train the model to predict **outputs** (food classes).

---

### Summary Recap (in terms of architecture)

| Component | Description                                      |
| --------- | ------------------------------------------------ |
| Inputs    | Image tensors                                    |
| Outputs   | Class labels                                     |
| Layers    | Functional units (attention, MLP, normalization) |
| Blocks    | Stacked layers forming encoder modules           |
| Model     | Collection of blocks                             |

## Deep Dive: Figure 1 – Architecture Overview

### What Figure 1 Shows

* An **image** is input.
* **Split into fixed-size patches.**
* **Each patch is linearly embedded** and has **position embeddings** added.
* This is passed into a **transformer encoder** with:

  * Normalization layers
  * Multi-head attention
  * Residual connections
  * MLP (multi-layer perceptron)

### Important Concepts:

* **Embedding** = Learnable representation
  → Initialized with random values, optimized over time.
* **Position Embedding** = Encodes the position of patches.
* **MLP** = Two-layer fully connected network (in this case).
* **Residual (Skip) Connection** = Adds original input to later outputs to preserve information.
* **Transformer Encoder** = A stack of blocks (Norm + Attention + Norm + MLP).
* **Block** = A set of layers grouped together.

---

## Mapping to FoodVision Mini

### Workflow:

## Understanding Equation 1

### Step-by-Step Summary:

1. **Input**: Image $X \in \mathbb{R}^{H \times W \times C}$

   * $H$: Height
   * $W$: Width
   * $C$: Color channels

2. **Patch Conversion**:

   * Image is split into square patches of size $P \times P$
   * The total number of patches:

     $$
     N = \frac{HW}{P^2}
     $$
   * Each patch is flattened and represented as a vector

3. **Patch Embeddings**:

   * Each flattened patch is linearly projected (embedded) to a vector of dimension $D$ using a **trainable projection**
   * This is referred to as the **Patch Embedding**

4. **Input Sequence**:

   * After projection, patches are turned into a sequence of vectors

     $$
     x_p \in \mathbb{R}^{N \times (P^2 \cdot C)}
     \rightarrow \text{Embedding} \rightarrow \mathbb{R}^{N \times D}
     $$
   * A **learnable class token** is prepended to the sequence
   * **Position embeddings** are added to retain patch order

### **Transformer Encoder Architecture Overview**

The **Transformer Encoder** is composed of alternating blocks of:

* **Multi-Head Self-Attention (MSA)**
* **MLP (Feed-Forward Neural Network)**
* **Layer Normalization (LayerNorm)**
* **Residual Connections** (also called Skip Connections)

Each layer follows this consistent structure:

-------------------code----------------------
Input → LayerNorm → [MSA or MLP] → Add Input (Residual)
-------------------code----------------------

---

### **Detailed Layer Analysis**

#### **1. Multi-Head Self-Attention (MSA) Block – Equation 2**

* Equation 2 corresponds to the **MSA block**.

* Structure:

  1. **Layer Normalization**
  2. **Multi-Head Self-Attention**
  3. **Residual Addition (input added back)**

* **Pseudocode** for Equation 2:

-------------------code----------------------
# Pseudocode for MSA Block
x = x_input
x = MSA(LayerNorm(x)) + x  # residual connection
-------------------code----------------------

#### **2. MLP Block – Equation 3**

* Equation 3 corresponds to the **MLP block**, which follows the MSA block.

* Structure:

  1. **Layer Normalization**
  2. **MLP (usually 2 linear layers with a non-linearity in between)**
  3. **Residual Addition**

* **Pseudocode** for Equation 3:

-------------------code----------------------
# Pseudocode for MLP Block
x = x_msa_output
x = MLP(LayerNorm(x)) + x  # residual connection
-------------------code----------------------

### **Residual Connections (Skip Connections)**

* Purpose: Helps mitigate vanishing gradients and training instability in deep networks.
* Mechanism: Adds the input of a block directly to its output.
* Example:

  * Given input `x`, and a function `F(x)` (e.g., MSA or MLP), the residual output is:
    `Output = F(x) + x`
* Benefit: Easier to learn residuals than full transformations; encourages identity mappings when needed.

### **Key Concepts Introduced**

#### **Multilayer Perceptron (MLP)**

* A **Multilayer Perceptron** is a feedforward artificial neural network.
* It maps input vectors to output vectors through one or more linear layers (with activations in between).
* In the ViT paper:

  * **Pre-training phase**: An MLP with **1 hidden layer** is used.
  * **Fine-tuning phase**: A **single linear layer** is used.

#### **BERT and Class Token**

* **BERT** is a Transformer-based model designed for natural language processing (NLP).
* The **class token** (`[CLS]`) is a learnable embedding prepended to the input sequence. It is used to aggregate the sequence information for classification.
* ViT adopts a similar idea by prepending a learnable **class embedding** to image patch embeddings.

---

### **Equation 4 Breakdown**

#### **From the Paper**

* Equation 4:
  **`y = LN(z₀ᴸ)`**

  * `z₀ᴸ`: Output of the **class token** from the **last encoder layer** (`L`)
  * `LN`: Layer Normalization
  * `y`: The final image representation, to be passed into a classification head (MLP)

#### **Classification Head**

* Applied on top of `z₀ᴸ`:

  * MLP with 1 hidden layer (pre-training)
  * Linear layer (fine-tuning)

---

### **Pseudocode for Equation 4**

-------------------code----------------------
# Output of MLP block is passed into the classification head
x = x_output_mlp_block  # This is z₀ᴸ

# Apply LayerNorm, followed by classification head
# For pre-training (MLP with one hidden layer):
y = MLP(LayerNorm(x))

# For fine-tuning (single linear layer):
y = Linear(LayerNorm(x))
-------------------code----------------------

3. **Equation 3**: MLP Block
   Applies LayerNorm → Feedforward MLP → Residual connection.

   Uses class token from final encoder output → LayerNorm → (MLP or Linear) → Final prediction `y`.

* Add \[CLS] token → sequence length becomes $196 + 1 = 197$

*** 240. Creating Patch Embeddings with a Convolutional Layer ***

## **Section 4.3: Creating Image Patches and Turning Them into Patch Embeddings**

---

### **Overview**

* This section focuses on turning an image into **patches** and then converting those patches into **embeddings**, using PyTorch layers.
* The process involves two key steps:

  1. Splitting the image into patches.
  2. Turning those patches into embeddings using a convolutional layer.

---

### Why do we turn **patches into embeddings** in ViT?

The Vision Transformer (ViT) treats an image kind of like a sentence made of words. But instead of words, we use **image patches** (small pieces of the image, like 16x16 pixel blocks).

But here’s the key:

> The transformer model doesn’t understand images — it understands **vectors** (lists of numbers).

So we need to **convert each image patch into a vector of numbers**. That’s what we call an **embedding**.

---

### Think of it like this:

* Imagine you cut a photo into small square tiles (patches).
* Now you want a computer to "read" them, but it doesn’t understand images or colors — only numbers.
* So you flatten each tile (like turning the tile into a long line of numbers) and use a small neural network (usually a linear layer) to **turn that into a fixed-size vector**.
* These vectors are now the "words" of our sentence — they’re the **embeddings**.

---

### Why embeddings are important:

* They give each patch a **standard format** the transformer can work with.
* They help the model learn what features are important in each part of the image.
* Without embeddings, the transformer wouldn’t know how to process visual information.

---

### In short:

> We turn patches into embeddings so that the transformer model can understand and learn from images — just like it understands and learns from words in text.


### **Why Do This?**

* Transformers require vector inputs.
* To apply transformers to images (like Vision Transformers), we need to convert image regions (patches) into numerical vectors called **embeddings**.
* This allows the model to process the image similarly to how it processes words in NLP.

---

### **Conceptual Analogy**

* **Image → Patches → Embeddings**
* Similar to how words are embedded in NLP, image patches are embedded in ViT.
* A **convolutional layer** with the right kernel and stride size acts as the patch extraction and embedding mechanism.

---

### **Using Convolution to Extract Patch Embeddings**

* We can simulate patch extraction using a `Conv2D` layer with:

  * **Kernel size** = patch size (e.g., 16x16)
  * **Stride** = patch size (to avoid overlap)
  * **In channels** = 3 (for RGB images)
  * **Out channels** = embedding dimension (e.g., 768)

#### PyTorch Code Snippet

-------------------code----------------------
import torch
from torch import nn

# Define patch size and embedding dimension
patch_size = 16
embedding_dim = 768

# Create the Conv2D layer for patch embedding
conv2d_layer = nn.Conv2d(
    in_channels=3, 
    out_channels=embedding_dim,
    kernel_size=patch_size, 
    stride=patch_size, 
    padding=0
)
-------------------code----------------------

* This operation:

  * Slides a 16×16 kernel across the image.
  * Outputs a tensor where each 16×16 patch is now represented by a 768-dimensional vector.
  * Creates a grid of patch embeddings (e.g., 14×14 grid for a 224×224 image).

---

### **Visual Interpretation**

* Using CNN explainer, a 2D convolution is shown sliding over an input image.
* Each step extracts a patch and converts it into a learnable feature map.
* These feature maps are the **patch embeddings**.

---

### **Output Shape Explanation**

Assuming input image size is 224×224:

* After `Conv2D`, output shape is:
  `[batch_size, embedding_dim, num_patches_height, num_patches_width]`
  e.g., `[1, 768, 14, 14]` → 196 patches in total.

---

### **Next Step: Flattening for Transformer Input**

* The ViT expects a flat sequence, not a grid.
* Use `torch.nn.Flatten` to flatten the spatial dimensions:

  -------------------code----------------------
  flatten = nn.Flatten(start_dim=2)
  patches = flatten(patch_embeddings)
  patches = patches.permute(0, 2, 1)  # Shape: [batch_size, num_patches, embedding_dim]
  -------------------code----------------------

---

### **Reference from ViT Paper**

* Section 3.1 of the paper mentions using CNN feature maps as an alternative to raw image patches.
* This hybrid approach means:

  * CNN can extract richer features.
  * Then we flatten and project these to the transformer’s input dimension.

---

### **Summary**

* Patch embeddings can be created using a convolutional layer.
* Set kernel size and stride to the patch size (e.g., 16).
* This generates a sequence of learnable embeddings, one for each patch.
* Flattening is the next step to prepare this data for input into a transformer.

*** 245. Creating the Class Token Embedding ***
## **Lecture Summary: Adding a Learnable Class Token in ViT**

### **Context**

* In the previous step, we built the **patch embedding layer** to turn an image into a sequence of embedded patches.
* Now, we're extending the sequence by adding a **learnable class token**—an essential step for enabling classification in ViT.
* This aligns with the ViT paper (Equation 1 and Figure 1), where the class token is prepended to the embedded patch sequence.

---

In simple terms:

### **A class token is a special learnable vector added to the input of a Vision Transformer (ViT) so the model can use it to make predictions.**

---

### Here's an analogy:

Imagine you're reading a book, and you want to write a summary of the whole thing.
You take notes on each chapter (these are like **patches** of the image).
But at the top of your notebook, you leave **one special page** to write your final summary.

That special page is the **class token**.

---

### More technically:

* The image is split into small parts (patches), and each part is turned into a vector.
* A **class token** is an extra vector added at the beginning.
* As the transformer processes all these vectors (patches + class token), the **class token gathers important information** from the whole image.
* At the end, we use **only the class token** to make a prediction (e.g., what object is in the image).

---

### Why use it?

Because transformers are designed for sequences (like words in a sentence), and the class token gives them **a dedicated place to store a summary** for classification.

## **Step-by-Step: Creating and Adding the Class Token**

### **1. Purpose of the Class Token**

* A **learnable embedding** prepended to the sequence of patch embeddings.
* Acts similarly to BERT’s `[CLS]` token.
* Used as the final output representation for classification.
* Final output shape becomes `[batch_size, num_patches + 1, embed_dim]`.

---

### **2. Verify Image Size Compatibility**

-------------------code----------------------

Use `nn.Parameter` so PyTorch tracks gradients and updates this token during training:

-------------------code----------------------

    torch.ones(1, 1, embed_dim),  # Shape: [1, 1, embedding_dim]
    requires_grad=True
)
-------------------code----------------------

* You can use `torch.rand` instead of `ones` for randomness:

  -------------------code----------------------

  -------------------code----------------------

---

### **4. Match Token Shape with Batch**

Broadcast the token across the batch:

-------------------code----------------------
batch_size = patch_embeddings.shape[0]  # From [B, N, D]

-------------------code----------------------

Use `torch.cat` to prepend along the patch (sequence) dimension (dim=1):

-------------------code----------------------

*** 247. Creating the Position Embedding ***
## **Lecture Summary: Position Embedding in Vision Transformers (ViT)**

### **Context**

* In the previous steps, we:

  * Split an image into patches.
  * Converted them into embeddings using a Conv2D layer.
  * Created and prepended a **learnable class token**.
* Now we are adding **position embeddings** to preserve the spatial layout of the original image.

---

## **4.7 Creating the Position Embedding**

### **Goal**

* Add a **learnable 1D position embedding** to the entire sequence (patch embeddings + class token).
* Final result: tensor of shape `[batch_size, num_patches + 1, embed_dim]` with positional information included.

---

### **Why Position Embedding?**

* When the image is turned into a sequence of patches, positional information is lost.
* Position embeddings help the transformer **understand the order and location** of patches.
* This allows the model to better reconstruct spatial relationships between parts of the image.

---

## **What is a Position Embedding?**

A **position embedding** is information added to each image patch (or token) to tell the model **where** it came from in the original image.

### Why do we need it?

Transformers **don’t understand order** by default.
Unlike CNNs or RNNs, transformers treat every token as **independent** unless we **explicitly tell them the order**.

So, we add a **position embedding** to each patch embedding to tell the model:

> "This patch is from the top-left",
> "This one is from the bottom-right", etc.

---

### Think of it like this:

Imagine someone sends you 10 puzzle pieces, but doesn't tell you where each one goes.
You'll struggle to build the full picture.

But if each piece comes **labeled with a position**, like “Row 1, Column 3”, you can reconstruct the image much better.

That label is like a **position embedding**.

---

## **What’s the difference between Class Token and Position Embedding?**

| Feature                        | Class Token                                           | Position Embedding                                      |
| ------------------------------ | ----------------------------------------------------- | ------------------------------------------------------- |
| **Purpose**                    | Used to summarize the entire input for classification | Used to tell the model where each patch comes from      |
| **Applies to**                 | One special token added at the start of the sequence  | Every token in the sequence (including the class token) |
| **Learnable?**                 | Yes (usually initialized randomly and trained)        | Yes (can be learned) or fixed (sinusoidal, etc.)        |
| **Shape (ViT Example)**        | `[1, 1, 768]`                                         | `[1, 197, 768]` (if 196 patches + 1 class token)        |
| **Used for final prediction?** | Yes, we use the class token as the final output       | No, position embeddings are just added to help learning |

---

### Summary:

* **Class token** = "Final summary" vector, used for prediction.
* **Position embedding** = "Location hint" added to each input so the model understands order or layout.



### **Steps to Add Position Embedding**

#### 1. **Calculate Number of Patches**

-------------------code----------------------
num_patches = int((height / patch_size) * (width / patch_size))  # Should be 196 for 224x224 with patch size 16
-------------------code----------------------

#### 2. **Get Embedding Dimension**

-------------------code----------------------
embedding_dim = patch_embedded_with_class.shape[-1]  # e.g., 768
-------------------code----------------------

#### 3. **Create Learnable Position Embedding**

-------------------code----------------------
position_embedding = nn.Parameter(
    torch.ones(1, num_patches + 1, embedding_dim)  # Shape: [1, 197, 768]
)
-------------------code----------------------

* `+1` accounts for the **class token** at the start.
* Using `torch.ones` for clarity; in practice, `torch.randn` is preferred.

#### 4. **Add Position Embedding to the Sequence**

-------------------code----------------------
patch_and_position_embedding = patch_embedded_with_class + position_embedding
-------------------code----------------------

---

### **Final Tensor Shape**

* The result is a tensor of shape:
  **`[batch_size, num_patches + 1, embedding_dim]`**, e.g., `[1, 197, 768]`
* This tensor now includes:

  * Embedded patches
  * Class token at the front
  * Positional context

* After class token: → `[1, 197, 768]`
* After adding position embedding: → still `[1, 197, 768]` but now enriched with spatial info.

### **Key Notes**

* **Class token** is for summarizing the image for classification.
* **Position embedding** encodes patch order/location.
* Both are **learnable parameters** (`nn.Parameter`) and updated during training.

### **Lecture Summary: Transformer Encoder – Multi-Head Self Attention (MSA) Block**

### **Transformer Encoder Overview**

* Transformer Encoder is made up of **two main blocks**:

  1. **MSA Block (Equation 2)**
  2. **MLP Block (Equation 3)**

Each block includes:

* **LayerNorm before each block** (pre-norm).
* **Residual connection** after each block.

So the data flow looks like:

-------------------code----------------------
Z’ = MSA(LayerNorm(Z)) + Z
-------------------code----------------------

(Residual = input + output of block)

---

### **Equation 2 – MSA Block**

### **What is Self-Attention?** (Simple Explanation)

**Self-attention** is a way for a model to **look at all parts of the input and decide which parts are important for each other**.

#### Example (Text):

> Sentence: "The animal didn't cross the road because it was too tired."

* What does **"it"** refer to?
  → "Animal", not "road".

Self-attention helps the model understand that **"it" should focus more on "animal"**, because they’re related.

#### Example (Image):

* You break an image into small patches.
* Self-attention helps each patch **"look at" all other patches** and decide:

  > "Which other patches should I care about to understand the image better?"

---

### **What is Multi-Head Self-Attention?** (Simple Explanation)

**Multi-head self-attention** is like **running self-attention several times in parallel**, each time with a different "focus" or "lens".

* Imagine you're looking at a photo with **different glasses**:

  * One pair focuses on **colors**
  * One on **shapes**
  * One on **edges**
* Each head learns to **focus on a different type of relationship** between the parts.

Afterward, the results from each head are **combined**, giving the model a richer understanding.

---

### Summary

| Term               | Meaning                                                                                                    |
| ------------------ | ---------------------------------------------------------------------------------------------------------- |
| **Self-Attention** | Each part of input decides which other parts to focus on.                                                  |
| **Multi-Head**     | Do self-attention multiple times in parallel, each with a different perspective, then combine the results. |



#### **Terminology**

* **MSA** = Multi-Head Self Attention
* Introduced in *Attention is All You Need* (Vaswani et al., 2017)

---

### **Understanding Self Attention**

Self-attention allows each token (e.g., image patch or word) to "attend to" other tokens in the sequence.

#### **Example from NLP**:

* Sentence: “The animal didn’t cross the road because it was too tired.”
* The word **"it"** attends most to **"animal"**.
* This concept is extended to **image patches**: which patch is most related to another?

---

### **How Self-Attention Works**

Self-attention maps a **Query (Q)**, **Key (K)**, and **Value (V)** to an output:

**Formula:**

-------------------code----------------------
Attention(Q, K, V) = softmax(QKᵀ / √d_k) · V
-------------------code----------------------

Where:

* `Q`, `K`, `V` = same input (self-attention)
* `d_k` = dimension of the key vector

#### **Steps**:

1. Compute dot product between `Q` and `Kᵀ`.
2. Scale the result by `√d_k`.
3. Apply softmax → get attention weights.
4. Multiply attention weights with `V`.

This results in a representation where each token's output is influenced by all others, weighted by learned importance.

---

### **Multi-Head Self Attention**

Instead of doing one attention calculation:

* Split the input into **multiple heads** (i.e., multiple subspaces).
* Perform self-attention for each head in parallel.
* Concatenate the results.
* Project the result back to original dimension.

---

### **PyTorch Implementation Tip**

Instead of writing MSA from scratch:

* Use built-in PyTorch module:

  -------------------code----------------------
  torch.nn.MultiheadAttention
  -------------------code----------------------
* `query`, `key`, and `value` are all the same input in self-attention.

---

### **Self-Attention in Vision Transformers (ViT)**

* Patchified image → sequence of embeddings.
* Self-attention helps the model learn relationships between patches:

  * Which patch is related to which others?
  * These relationships are **learned**, not hardcoded.

## Lecture Summary: Multi-Head Self-Attention & Layer Normalization (Transformer Encoder - Equation 2)

---

### **Recap of Previous Video**

* **Multi-Head Self-Attention (MSA)**:

  * Helps the model learn **which parts of a sequence should focus on others**.
  * In our case: Embedded **image patches** attending to each other.
  * The model learns relationships between patches automatically.
  * This learning leads to better **representations** of the image content.

---

### **Understanding MSA Mechanism**

* **"Self"** attention: Input attends to **itself** (i.e., all parts of a sequence).
* Each **patch embedding** is processed to determine which other patches are most relevant.
* Allows patches to "communicate" and **influence each other's representations**.

---

### **MSA in PyTorch**

* PyTorch provides a ready-to-use layer:

  -------------------code----------------------
  torch.nn.MultiheadAttention
  -------------------code----------------------

* Takes three inputs:

  * **Query (Q)**
  * **Key (K)**
  * **Value (V)**

* In **self-attention**, all three are usually the **same input**:

  -------------------code----------------------
  Q = K = V = normalized_input
  -------------------code----------------------

* These are derived from the **same embedding (X)**, passed through **LayerNorm** before attention.

---

### **Layer Normalization (LayerNorm)**

#### What does **"normalize"** mean in simple words?

**Normalize** means to **make things more consistent or balanced**.

In machine learning, when we **normalize data**, we usually adjust it so that:

* The **average (mean)** is around **0**
* The **spread (standard deviation)** is around **1**

---

### Why do we normalize?

Imagine you're comparing test scores from two students:

* One scored out of 100
* Another out of 10

You can’t fairly compare them unless you **bring them to the same scale** — that’s normalization.

In deep learning, we normalize to:

* **Stabilize training**
* **Make learning faster**
* **Help the model treat each feature equally**

---

### Simple Analogy

Imagine you're walking down stairs:

* If each stair is a different height, it’s **hard** to walk smoothly.
* If all stairs are the **same size**, you can walk **faster and easier**.

Normalization makes the “stairs” (data) more **even**.

---

### Example:

Before normalization:

-------------------code----------------------
[10, 20, 30]
-------------------code----------------------

After normalization:

-------------------code----------------------
[-1.2, 0.0, 1.2]
-------------------code----------------------

* Mean is now 0
* Spread is balanced

---

#### Definition:

> LayerNorm is a technique to **normalize the distribution** of intermediate layer activations across the embedding dimension.

#### Benefits:

* Smoother gradients
* Faster training
* Better generalization

#### What it does:

* Makes the **mean = 0** and **standard deviation = 1** across the embedding dimension.
* Think of it as adjusting the "scale" of each input feature to be consistent.

#### PyTorch Implementation:

-------------------code----------------------
torch.nn.LayerNorm(normalized_shape)
-------------------code----------------------

* `normalized_shape` = the embedding dimension
  (e.g., `768` if that's the patch embedding size)

---

### Analogy: LayerNorm as Equal Stairs

* Imagine training (gradient descent) as walking **down a staircase**.
* If the stairs are all **different heights and widths**, it’s hard to walk smoothly.
* LayerNorm **standardizes** all steps to be the same:

  * Easier to step down → **faster and more stable training**.

---

### Bringing it Together – Equation 2 (MSA Block)

#### **What we've got:**

* **LayerNorm** before attention
* **Multi-Head Self Attention (MSA)** layer
* **Residual connection** (input + output)

#### **Structure:**

-------------------code----------------------
Z' = MSA(LayerNorm(X)) + X
-------------------code----------------------

### Your Coding Challenge (Before Next Video)

Create a class that wraps all this:

-------------------code----------------------
class MultiHeadSelfAttentionBlock(nn.Module):
    def __init__(self, embed_dim, num_heads):
        super().__init__()
        self.layernorm = nn.LayerNorm(embed_dim)
        self.msa = nn.MultiheadAttention(embed_dim, num_heads)

    def forward(self, x):
        # x: (sequence_length, batch_size, embed_dim)
        x_norm = self.layernorm(x)
        attn_output, _ = self.msa(x_norm, x_norm, x_norm)
        return attn_output + x  # Residual connection
-------------------code----------------------
