*** 329. Introduction to PyTorch 2.0 ***
**Lecture Summary: Introduction to PyTorch 2.0**

**1. Overview of PyTorch 2.0 Release**

* PyTorch 2.0 officially released, with the primary improvement focused on speed.
* The key new feature is `torch.compile`, a backward-compatible function that compiles models to optimize performance.
* After creating a model, passing it to `torch.compile` returns a compiled model that offers speed improvements during training and inference, especially on newer GPUs.

**2. Performance Gains**

* PyTorch tested `torch.compile` on 163 open-source models (from Huggingface Transformers, timm, Torchvision, and TorchBench).
* Tests used mixed precision (automatic mixed precision, Float16) and Float32 training.
* Results showed an average speed increase of 43% in training on Nvidia A100 GPUs.
* Personal benchmarks showed:

  * Larger batch and data sizes benefit more from `torch.compile`.
  * The first training epoch is slower, but subsequent epochs run faster.
  * Speed improvements observed were about 10% on local RTX 40 and A100 GPUs.
* Further exploration needed with mixed precision training, transformer architectures, and longer training runs, where bigger gains are expected.

**3. Technologies Behind `torch.compile`**

* `torch.compile` integrates several components:

  * Torch Dynamo
  * Aot Autograd
  * Torch Inductor
* Two main optimization techniques it offers:

  1. **Fusion (Operator Fusion)**
  2. **Graph Capture (Graph Tracing)**

**4. Fusion (Operator Fusion)**

* Fusion combines multiple operations into fewer operations to reduce overhead.
* Modern GPUs have very high compute power; the bottleneck is often memory bandwidth (speed of moving data between CPU and GPU).
* Fusion minimizes how often intermediate results are written to and read from memory, reducing bandwidth costs.
* Analogy:

  * Without fusion: Adding ingredients one by one and blending repeatedly.
  * With fusion: Adding all ingredients first, then blending once — more efficient.

**5. Graph Capture (Graph Tracing)**

* Graph capture records the sequence of operations in advance.
* Without it, operations are interpreted and executed one-by-one, causing overhead.
* Analogy:

  * Without graph capture: Driving in a new area, thinking about every turn as you go.
  * With graph capture: Driving in your own neighborhood, knowing the route ahead of time.
* Upfront time is spent recording the graph, but later executions are faster.

**6. Additional Resources**

* For a deeper understanding of fusion, memory bandwidth, and overhead, see "Making Deep Learning Go BR from First Principles" by Horace Hare.

**7. Other Notable PyTorch 2.0 Features**

* Faster Transformers is now stable, improving transformer-style model speed.
* Universal device setup introduced via a context manager or global setting.
* Enhanced Metal Performance Shaders improve PyTorch support on Mac.
* Domain-specific library upgrades in:

  * Torchvision
  * Torchtext
  * Torchrec
  * Torchaudio
  * And others.

**2. Backward Compatibility and Familiarity**

* PyTorch 2.0 is fully backward compatible with PyTorch 1.x versions.
* Existing PyTorch 1.x code, including model definitions and training routines, continue to work as before.

**3. Main New Feature: `torch.compile`**

* Example:

  * Define a model as usual, e.g., `model = torchvision.models.resnet50()`
  * Wrap the model with `torch.compile(model)` to get an optimized compiled version.
* The compiled model is a normal PyTorch model enhanced with optimizations that improve speed.
* Training and testing code remains unchanged; the compilation step simply replaces the original model with the compiled one.

**4. Compatibility with Models**

* PyTorch 2.0 aims to support *all* models, meaning `torch.compile` should work with virtually any PyTorch model.
* This broad compatibility is a key design goal.

**5. Current Caveats and Limitations**

* Some features, such as model exporting after compilation, currently have limitations.
* Exporting compiled models for deployment might not work on all devices yet.
* The PyTorch development team is aware and plans to address these issues in future releases.
* Users should check the latest PyTorch 2.0 blog and release notes for updates regarding these caveats.

*** 334. Getting Info from Our GPUs and Seeing if They're Capable of Using PyTorch 2 ***
## PyTorch 2.0 GPU Compatibility and Performance Notes

### 1. PyTorch 2.0 Key Feature

* **Main feature**: `torch.compile` — optimizes models via **fusion** and **graph capture**.
* Works **best** on **newer NVIDIA GPUs**.

---

### 2. What is a "Newer" NVIDIA GPU?

* Determined by **Compute Capability** score.
* **Higher score = newer and more capable GPU**.

**Examples:**

* **A100**: Compute Capability 8.0
* **H100**: Compute Capability 9.0
* **L4**: Compute Capability 8.9
* **T4**: Compute Capability 7.5
* **V100**: Compute Capability 7.0
* **RTX 4090**: Consumer GPU, high performance.
* **RTX 3090**: Consumer GPU, good but not as capable as data center GPUs.
* **Titan RTX**: 7.5

---

### 3. Minimum Recommended Compute Capability

* **8.0 or higher** → can leverage most PyTorch 2.0 speed features.
* **Below 8.0** → PyTorch 2.0 still works (backwards compatible) but speed improvements may be smaller.

---

### 4. Desktop vs Data Center GPUs

* **Desktop Class**: GPUs like RTX 3090 (consumer hardware).
* **Data Center Class**: GPUs like A100, H100 (enterprise/cloud hardware).
* **Same architecture** (e.g., Ampere) ≠ same performance.

  * Data center GPUs often have **extra hardware capabilities** for higher performance.

---

### 5. Checking GPU Compatibility

**Method:**

1. Check **NVIDIA GPU compatibility list** online.
2. Or use PyTorch's built-in function:

   -------------------code----------------------
   torch.cuda.get_device_capability()
   -------------------code----------------------

   * Returns a tuple: `(major, minor)`
   * Example: `(8, 0)` → Compute Capability 8.0

**Logic:**

* If capability ≥ 8.0 → PyTorch 2.0 speed features fully available.
* If < 8.0 → Features still work, but speed gains are smaller.

---

### 6. Caveats and Performance Notes

* Data center GPUs usually yield **greater speedups** than desktop GPUs.
* Even GPUs with the **same architecture** may differ in performance due to hardware design.
* If using cloud environments (Google Colab Pro, AWS, etc.), GPU type impacts results.
